## 원인과 계약

- 드래그 placeholder가 36px의 실제 Row를 추가하여 목표 Row를 밀었음. 수정 전 회귀 테스트에서 대상 y가 36px 변경되는 실패 확인.
- 가상 스크롤은 논리 높이를 최대 1,500,000px의 물리 높이로 압축하지만 실제 Row 높이는 그대로임. 고정 높이의 render offset에서 전체 spacer를 축소하던 계산을 바로잡음.
- 순서 변경 뒤 기존 anchor Row를 따라가던 보정은 사용자가 놓은 화면 위치를 바꿈. 로컬 Row drop에서는 스크롤 위치를 보존함.
- Core의 leaf-target 계약은 **대상 Row의 기존 인덱스에 배치**하는 방식이며 변경하지 않음. 아래로 이동하면 대상 바로 뒤, 위로 이동하면 대상 바로 앞에 배치됨. 회귀 테스트도 해당 계약을 검증함.
- 빈 TSV Cell은 값 삭제를 뜻하므로 끝 탭을 무조건 trim하는 방식은 적용하지 않음.

## 실제 브라우저 직접 조작

In-app Browser에서 코드로 데이터나 scrollTop을 바꾸지 않고 클릭·우클릭·드래그·휠·키보드를 사용함. DOM 조회는 결과 확인에만 사용.

- Header 숨김 후 PageDown/휠: scrollTop 638에서도 고정 viewport border 1px 유지. 같은 화면에서 name=left, age=right, active=center 확인.
- Component Button: 첫 행을 네 번째 위치로 드래그한 뒤 `button-a / Data 1 Button / Owner`가 함께 이동.
- 두 값 원본을 Cmd+A/C로 복사하여 첫 Cell에 Cmd+V: `Sheet 1 / 100 / Value 1 / Locked 1`, 세 번째 값 유지.
- Context 우클릭 추가: 30→31 Row, 새 Row 실제 출력. 새 Row 우클릭 삭제: 31→30 Row, 해당 ID 제거.
- 가상 Row Grouping: 휠로 scrollTop 756000 이동. row 50412를 인덱스 50415로 아래 드래그 후 스크롤 756000 유지. 위로 되돌린 뒤 인덱스 50411 복원 및 스크롤 유지.
- Row 기본의 이동 금지 Data 2는 선택 가능, 잠금 Data 4는 클릭해도 선택되지 않음.
- Column Filtering의 Empty 설명과 빈 그룹, Row Drag handle 0개 확인.
- 직접 조작용 브라우저의 스크린샷 API는 캡처 실패를 반환했음. 저장된 회귀 테스트 스크린샷은 자동 테스트 증거이며 직접 조작 캡처로 주장하지 않음.
