# 2026-08-28 0.1.8 Column Pinning 및 Cross-Table Drag 로컬 구현

## 요약

## 실패 분류 및 수정 근거

- Cross-Table 이동 후 target data는 3개였지만 `pagination` 미지정 Table이 초기 2개 Row의 내부 pageSize를 보존하여 세 번째 Row를 숨겼다. 무페이지네이션 controlled data 증가 시 전체 Row 수를 다시 반영하도록 수정하고 component regression을 추가했다.
- 기존 local Row Drag의 pointerup이 렌더된 placeholder 위에 놓이면 신규 cross-target fallback이 직전 local target을 invalid로 덮어썼다. 같은 Table 내부 placeholder에서는 직전 유효 target을 보존하도록 수정했다.
- target edge auto-scroll의 첫 animation frame이 delta 0을 이동 없음으로 처리해 loop를 즉시 종료했다. 첫 frame은 timestamp 기준만 설정하고 다음 frame을 예약하도록 수정했으며 실제 long target Table E2E로 확인했다.
- 최초 전체 unit 실패 6건은 신규 Playground Feature ID/번역/README heading 기준 목록 누락이었다. 신규 공개 항목을 canonical order와 localization contract에 등록해 해결했다.
- 최초 package artifact 검사는 sandbox 기본 npm cache/log 경로 제한으로 fail-closed 됐다. `/tmp` 격리 cache에서 동일 검사와 exact consumer smoke가 통과하여 실행 환경 실패로 분류했다.
- physical-scrollbar memory test는 한 실행에서 변경본 1,223→3,050 nodes, 변경 전 HEAD 1,213→3,008 nodes로 동일 실패했다. 양쪽 모두 `documents=2`, live element와 heap/event listener는 기준 범위였으므로 신규 기능 누수가 아닌 현 브라우저의 retained document counter 변동으로 분류하고 threshold를 유지했다. 최종 전체 performance 실행은 baseline 3,047, 복귀 3,050으로 28/28 통과했다.
- 초기 auto-scroll E2E 좌표는 target bottom이 browser viewport 밖에 있어 hit target이 없었다. 실제 geometry를 측정하고 target edge가 화면에 보이는 viewport 조건을 명시해 assertion을 유지했다.
