## 원인 및 수정

- #74의 lockfile에 포함된 source-map-js 1.2.1의 high advisory를 확인했다. 기존 범위의 1.2.2로만 갱신한 뒤 npm audit은 개발 및 런타임을 포함하여 0건이다.
- #75는 lru-cache 11.5.3의 BlueOak-1.0.0에 대한 버전 한정 승인이 누락되어 라이선스 게이트가 실패했다. 기존 승인된 11.5.2와 신규 버전의 npm artifact 내 라이선스 본문이 동일함을 확인했다. 사용자가 개발 도구 전용·수정/복사/번들/npm 배포 제외 조건으로 승인했고, 정확한 버전의 승인 기록을 추가했다. 전후 license-check 실패/통과를 확인했다.
- #74·#76 기존 CI trace에서 드래그 입력이 높이 720px viewport의 y=744px에서 해제된 것을 확인했다. source hover로 위치가 변경된 이후 drop target을 다시 스크롤하지 않은 테스트 helper 문제다. 화면 밖 대상에 대한 회귀 조건에서 원본 helper 실패를 재현하고, mouse down 후 target을 다시 스크롤한 뒤 좌표를 계산하도록 수정했다. 업무 드래그 코드는 변경하지 않았다.
- #74 Context Menu trace는 하단 버튼 아래 y 좌표를 그대로 사용해 메뉴가 화면 밖에 위치한 경우다. 하단 버튼 회귀 테스트에서 viewport ratio 0을 재현했고, 우클릭 경로와 동일한 화면 경계 제한을 버튼 경로에도 적용했다.
- 최종 전체 E2E에서 Column Pinning 2건이 scrollLeft 0으로 실패했고, 동일 spec 재검증에서도 재현했다. 휠 입력 후 네 영역의 값이 모두 0인 상태를 동기화 완료로 판단하는 검사 순서 문제였다. 실제 스크롤 시작을 먼저 기다린 뒤 기존 동기화 및 끝 좌표 검사를 유지했으며, 관련 5/5 테스트가 통과했다.
