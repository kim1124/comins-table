## 요약

### Task 1 - private virtual layout primitives

- typed Row ID를 보존하는 private data/group Slot, Detail height 정규화,
  Fenwick height index, bounded physical/logical scroll mapping, range lookup,
  width-aware measurement cache, anchor capture·fallback primitives를 추가했다.
- 일반 Row height와 public `getCominsVirtualRows` 계약은 변경하지 않고
  mixed Detail layout 기반을 `src/virtual-layout.ts` 내부에 한정했다.

### Task 2 - controlled public API and semantic Detail Row

- flat table에 `expandedRowIds`, `onChangeExpandedRowIds`,
  `isRowExpandable`, `getRowDetailHeight`, `estimatedRowDetailHeight`,
  `renderRowDetail` controlled API를 추가했다.
- Tree Grid type과 runtime wrapper는 Row Detail props를 거부·제거하며,
  Detail은 owner 다음의 semantic `<tr><td colSpan><div role="region">`
  구조로만 렌더링한다.
- disclosure event isolation, mounted-only `aria-controls`, labelled region,
  callback 없는 disabled read-only 상태, fixed height CSS 계약을 고정했다.

### Task 3 - fixed Detail mixed-height virtualization

- effective Detail이 없으면 기존 fixed arithmetic 경로를 유지하고, Detail이
  있는 경우에만 전체 owner projection과 height index를 구성한다.
- owner와 Detail을 하나의 Slot으로 range에 포함하고, 1,500,000px 물리
  scrollHeight cap, intra-Slot render offset, sorting·collapse·projection rebuild
  anchor 복원을 적용했다.

### Task 4 - automatic measurement and correction

- mounted `"auto"` Detail content만 한 table instance의 shared
  `ResizeObserver`로 측정하고, border-box height와 rounded width cache를
  사용한다. fixed Detail은 측정하지 않는다.
- 0.5px 미만 delta 무시, width mismatch estimate fallback, cache eviction,
  ResizeObserver 부재 시 최초 rect 측정, immutable projection rebuild와
  logical-anchor transaction을 구현했다.

### Task 5 - compatibility, Playground, and public documentation

- sorting, pagination dormant ID, lazy/infinite owner count, Row move,
  selection, clipboard, context/double-click, loading·empty·filler·Summary,
  focus restore, horizontal layout의 owner-only 계약을 검증했다.
- `/examples/row-expand`에 fixed, automatic growth, viewport-tall,
  read-only, non-expandable 예제를 등록하고 option guide와 code sample을
  연결했다.
- README, virtualization guide, Row Expand 영문·한글 guide에 controlled
  write-back, semantic DOM, fixed/auto height, 성능 및 unsupported 경계를
  문서화했다.

### Task 6 - performance, memory, and completion gates

- 100,000행 Virtualization 화면에 query 기반 `row-detail-fixed`,
  `row-detail-auto` 성능 fixture를 추가했다. 일반 경로는 Row Detail props를
  전달하지 않아 기존 fixed arithmetic 경계를 유지한다.
- fixed fixture는 360px Detail 한 개를, automatic fixture는 측정 가능한
  bounded Detail 한 개와 최대 네 번의 성장 동작을 제공한다.
- 일반 경로의 상단·중단·하단 owner Row 수, fixed/automatic mixed-height
  Row 수, 물리 scrollHeight, scrollbar drag, 후속 wheel latency, 반복
  expand/collapse DOM 경계를 성능 테스트로 고정했다.
- Row Expand fixed/automatic 예제를 열고 성장·column resize·collapse를
  10회 반복한 뒤 Getting Started로 이동해 observer target과 DevTools
  memory counter가 회복되는 시나리오를 추가했다.
- automatic Detail 성장의 압축 스크롤 앵커가 브라우저의 정수
  `scrollTop` 반올림 뒤 1px 계약을 초과하는 직접 발견을 수정했다.
  ResizeObserver와 일반 layout correction이 앵커를 중복 소유하지 않도록
  이전 projection의 in-place mutation과 observer 직접 보정을 제거하고,
  다음 immutable projection에서 단일 logical-anchor transaction을 한 번만
  소비한다.
- Task 6 코드 리뷰에서 observer가 pending revision을 예약한 직후 같은
  React batch의 실제 user scroll이 먼저 발생하면 stale correction이 사용자
  위치를 되돌리는 race를 확인했다. pending revision 취소 상태와 layout
  effect의 revision 일치 검증을 scroll write 전·후에 적용했다.
- 최종 whole-branch review의 Important 7건과 Minor 3건을 한 wave에서
  처리했다. mixed→fixed remount focus, nonvirtual Detail-aware filler,
  lazy Detail observer lifecycle, pagination 밖 dormant callback, 동일 Document
  10-cycle memory audit, README controlled write-back, 전체 작업 보고서와
  Slot key·한글 문서·unused ref 정리를 포함한다.

## 잔여 리스크

- application이 제공하는 automatic Detail content는 라이브러리가 높이를
  제한하지 않는다. 무제한 content는 logical height와 측정 빈도를
  증가시킬 수 있으므로 consumer가 bounded UI를 제공해야 한다.
- 브라우저 제품·성능 검증은 Chromium 기준이다. Firefox, WebKit, Safari
  및 물리 모바일 환경은 이번 Task 6 검증 범위가 아니다.
- 필수 gate 기준으로 알려진 미해결 제품 동작 또는 테스트 계약은 없다.
