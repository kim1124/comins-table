# 2026-11-13 헤더 등록 저장소 수정

## 요약

컬럼 그룹과 일반 헤더가 공유하는 네이티브 input/change 등록 여부를 모듈 전역 WeakSet에서 해당 DOM의 비공개 Symbol 원시값으로 옮겼다. 반복 Unmount 후 대상 DOM이 해제되어도 남던 WeakSet backing 용량 이력을 제거한다. 이벤트 본문·capture·공개 API·SSR HTML은 유지한다.

이 수정은 불필요한 SDK 등록 저장소 문제에 한정된다. 강한 DOM 누수나 기존 전체 화면 JS Heap 15% 증가의 원인 전체가 해결됐다는 결론은 아니다. 기존 수치 FAIL과 출시 보류를 유지한다.

## 변경 파일

- `src/index.tsx`: 헤더 소유 등록 표식.
- `test/column-placeholder-native-boundary.test.tsx`: StrictMode 재연결, 복수 테이블·그룹/일반 헤더, native input/change 차단 회귀.
- `test/playwright/helpers/weak-registry-snapshot.ts`, `test/weak-registry-snapshot.test.ts`: 지정 저장소의 strong 경로·ContextCell·WeakMap 조건부 경로와 교정 표본 검사. 네이티브 opaque ephemeron 경로는 제외하고 개수를 기록한다. 범용 보유량 분석기가 아니다.
- `test/playwright/specs/column-native-bookkeeping.spec.ts`: 실제 SPA에서 같은 App의 강한 보유/해제 교정, 소유자 없는 초기 상태·warmup10·300회 후 저장소 비교.
- `docs/maintenance/memory-validation-contract.md`, `CHANGELOG.md`: 보조 회귀 범위와 수정 기록.
