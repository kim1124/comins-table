## 변경

- `package.json`, `package-lock.json`: 버전을 0.1.11에서 0.2.0으로 맞췄다. `/core`의 중립 계약 전환은 0.x 계열의 호환성 변경으로 minor 버전을 올린다. 의존성·peer 범위·exports·files는 유지한다.
- `README.md`, `CHANGELOG.md`, `docs/user/26-migration-0.2.0.md`, `docs/ko/26-migration-0.2.0.md`: 새 버전의 소스 준비 상태, Core import 전환, 미배포 상태와 기존 0.1.11 GIF 기록을 구분했다. README 구조 축약은 별도 후속 작업으로 남긴다.
- `.github/workflows/publish.yml`: 기존 소비자 검사 뒤에 Core 및 React 18/19 공개 패키지 소비자 검사를 연결했다. 두 검사는 동일한 `steps.pack.outputs.package-file`을 사용하며, 실패하면 artifact 업로드와 staging으로 진행하지 않는다.
- 본 보고서: 검증 결과와 남은 승인 경계를 기록한다.

## 남은 단계와 제한

- 정식 배포 artifact는 승인 후 GitHub 릴리스 workflow가 생성·검증·staging하는 파일이다. 위 로컬 진단 파일로 정식 Candidate/Staged/Published/Closed 상태를 주장하지 않는다.
- 공개 정책인 `SECURITY.md`는 아직 0.1.x 지원만 표시한다. 제안: 기존 지원 행을 유지하고 `| 0.2.x | Yes |`를 추가한다. 공개 지원 정책 변경은 Comins Contract의 명시 승인 대상이므로 이번 작업에서는 적용하지 않았다.
- 공개 릴리스 승인 시 CHANGELOG의 release 날짜와 README/한·영 migration의 미배포 표기를 확정하고, 준비 브랜치의 원격 PR 및 필수 CI를 거쳐야 한다.
- 이번 변경은 라이브러리·Playground 런타임, 스타일, 브라우저 상호작용, 성능 코드를 수정하지 않았다. E2E·Astra UI·성능 검사를 로컬에서 반복하지 않았다. 배포 workflow는 정식 artifact 생성 전에 `verify:local`을 다시 실행한다.
- 이번 작업에서 원격 쓰기·게시를 수행하지 않았다. 기존 Core 작업 브랜치와 사용자가 실행을 요청한 Playground 서버를 유지한다.
