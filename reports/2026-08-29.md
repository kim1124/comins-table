- Playground의 공개 Feature 25개 모두에 canonical route smoke와 기능 전용 browser spec 소유권이 존재한다.

- 로컬 Playwright는 항상 single worker, local retry 0, `failOnFlakyTests: true`, `forbidOnly: true`로 실행되며 `verify:full`은 fast gate → 일반 E2E → performance 순서를 포함한다.

## 발견 및 교정 사항

1. 전체 route smoke가 과거 22개 hard-coded 목록에 머물러 Row Expand, Column Pinning, Cross-Table Drag를 누락했다. 25개 canonical manifest 기반으로 교체했다.
2. package public export인 root `styles.css` 단독 변경이 기존 inline CI classifier에서 Browser E2E를 실행하지 않았다. pure classifier와 Unit 계약을 추가하고 workflow가 해당 classifier를 사용하도록 변경했다.
3. `forbidOnly`와 flaky retry 실패 처리가 CI에서만 강제됐고 local `verify:full`은 performance를 포함하지 않았다. local/CI 공통 fail-closed 설정과 명시적 `verify:local`, `verify:full` 순서로 교정했다.
4. 일반 Row event E2E에 350ms 고정 대기가 있었다. 제거 후 해당 spec 25건을 `repeat-each=5`, single worker로 실행해 모두 통과했다.
5. README GIF workflow 테스트가 제거된 inline regex 문자열을 계속 요구해 올바른 classifier 구현을 실패로 보고했다. 실행 가능한 `classifyVerificationScope()` 결과를 직접 검증하도록 교정했다.
6. physical-scrollbar memory test가 `page.goto()`로 새 문서를 반복 생성하고 CDP `Memory.getDOMCounters`의 BFCache/retained document node를 제품 누수처럼 비교했다. 최초 진입만 document navigation으로 두고 fixture 진입과 복귀를 동일 문서 SPA lifecycle로 바꿨다. 제품 threshold는 유지한 상태로 통과했다.
7. 전체 memory audit도 기본 화면 복귀에 `page.goto()`를 사용하고 Header Drag 전에 1,100ms 고정 대기를 사용했다. 실제 sidebar navigation과 `data-column-placeholder` 상태 확인으로 교체했으며 6/6 통과했다.
8. classic vertical scrollbar gutter가 있는 환경에서 Body와 bottom rail의 horizontal end range가 15px 달랐다. Body의 실제 scroll content width를 Header, Summary, bottom rail에 동기화하고 reserved-gutter E2E를 추가했다. 첫 GitHub-hosted 실행에서 Linux Chromium이 동기화 surface를 부모 폭으로 stretch하는 15px 차이를 추가로 검출해, Header·Summary·bottom rail이 측정된 Body viewport 폭을 실제 사용하도록 cross-axis stretch를 차단했다.
9. Cross-Table Drag는 Row가 있는 target만 검증하고 빈 Body 하단 영역 drop을 직접 검증하지 않았다. 실제 pointer hit-test와 transfer/focus 결과를 확인하는 browser case를 추가했다.
10. Playwright 실패 artifact 보존 기간을 3일에서 14일로 늘려 PR 실패 증거의 사후 분석 가능 기간을 확보했다.
11. 개별 performance 실행은 통과했지만 `verify:full` 순서에서 Component memory heap이 10% 기준을 약 0.5%p 초과하는 변동을 재현했다. 최초 Component 상호작용을 warm-up한 뒤 mount/unmount 3회를 측정하도록 변경해 일회성 V8 비용과 반복 누수를 분리했다. 동일 임계값으로 5/5 반복 통과했다.
12. Feature lifecycle memory는 baseline 1회와 측정 5회의 route workload가 비대칭이어서 10% 기준을 약 0.03%p 초과했다. warm-up과 측정에 동일한 5회 순환을 적용했으며 동일 임계값으로 5/5 반복 통과했다.
13. 100,000 Row virtual scroll memory는 route warm-up만 수행한 baseline과 최초 down/up workload 이후의 heap을 비교해 독립 반복 5회 중 1회를 10% 기준 약 0.28%p 초과로 보고했다. 동일한 down/up workload를 warm-up과 측정에 적용했으며 임계값을 유지한 상태로 5/5 반복 통과했다.

## 테스트 패턴 분류

- 일반 E2E에는 `waitForTimeout`이 0건이다. 고정 대기 8건은 GC/CDP metric 반영과 물리 scrollbar gesture를 다루는 performance harness 3개 파일에만 남아 있다.
- `test.skip`, `test.fixme`, `test.only`는 Playwright spec에 0건이며 Unit 계약이 재유입을 차단한다.
- programmatic `scrollTop`/`scrollLeft`와 synthetic `scroll`은 100,000 Row 위치 설정, remote load trigger, memory sampling처럼 큰 상태를 결정적으로 만드는 setup에 한정한다. Row/Group/Header Drag, resize, clipboard, context menu와 Column Pinning의 주 사용자 경로는 실제 mouse, keyboard, wheel 입력으로 검증한다.
- geometry assertion은 sticky 위치, resize clamp, drag target, overflow containment과 scrollbar boundary처럼 좌표가 제품 계약인 경우에 유지한다.
- CI required gate는 security, selected fast gate, selected Chromium E2E를 수행한다. 성능/CDP 계측은 로컬 `verify:full`에서 single worker로 수행하며 CI 일반 E2E와 섞지 않는다.

## 실패 분류

- 첫 focused performance 실행의 `listen EPERM 127.0.0.1:4002`는 Playwright webServer가 assertion 전에 차단된 sandbox 실행 환경 실패다. 별도 Linux/container 환경을 만들지 않고 동일 프로젝트 명령을 허용된 localhost 환경에서 재실행했다.
- 첫 전체 performance는 physical-scrollbar memory 1건이 `nodes 1,223 → 3,051`, `documents 1 → 2`로 실패했지만 현재 문서의 `liveElementCount`는 721로 동일했다. 동일 문서 SPA lifecycle로 테스트 계약을 교정한 최종 실행은 threshold 변경 없이 28/28 통과했다.
- 첫 전체 Unit은 README GIF test 1건이 삭제된 inline CI pattern을 요구해 373/374였다. pure classifier 실행 결과를 검증하도록 수정한 최종 Unit은 374/374다.
- 첫 `verify:full` 통합 실행은 Component memory heap 1건이 10% 기준을 약 0.5%p 초과했고 serial 후속 3건은 실행되지 않았다. 5회 독립 반복에서 4 pass/1 fail로 one-time heap baseline 변동을 확인했다. workload warm-up 후 mount/unmount 3회를 측정하는 강화된 계약은 5/5 통과했다.
- 다음 전체 memory audit은 Feature lifecycle의 1회 baseline 대비 5회 측정 workload 비대칭을 10% 기준 약 0.03%p 초과로 검출했다. 양쪽을 동일 5회 workload로 맞춘 강화된 계약은 5/5 통과했으며 최종 `verify:full`의 performance 28/28에도 포함됐다.
- 첫 GitHub-hosted 실행 `33220339054`는 Linux Chromium에서 Body `948/963`과 동기화 surface의 15px range 차이를 2건 검출했다. 실패 trace의 target width와 scroll range를 대조해 flex cross-axis stretch를 제품 원인으로 분류했고, assertion 완화 없이 measured Body viewport 폭을 강제했다.
- CSS 수정 후 첫 `verify:full`은 100,000 Row memory heap이 10% 기준을 41,404 bytes 초과했고, 독립 5회 반복에서도 1회 재현됐다. DOM, document와 listener는 회수됐으며 baseline에 동일 down/up workload가 없던 비대칭을 교정한 뒤 5/5 반복과 최종 performance 28/28을 통과했다.
