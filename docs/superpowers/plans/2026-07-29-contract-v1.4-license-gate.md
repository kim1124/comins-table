# Comins Table Contract v1.4 License Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Contract v1.4에 맞는 얇고 결정적인 라이선스 검사를 Data Table의 baseline과 exact npm artifact 경계에 추가한다.

**Architecture:** `package-lock.json`의 표준 라이선스 metadata를 routine dependency inventory로 사용하고, 자동 통과 목록 밖이거나 모호·제한적인 항목만 작은 scoped approval 파일로 분리한다. 저장소에 실제 배포되는 Spoqa font와 생성 GIF는 별도의 작은 asset evidence로 검증하고, 기존 `verify-package-artifact.mjs`가 새 checker를 exact tarball에 적용하도록 연결한다. v1.3 worktree의 177개 transitive evidence, hash graph, 대형 JSON Schema는 재사용하지 않는다.

**Tech Stack:** Node.js 24 ESM, npm lockfile v3, Node test runner, Vitest, Vite, GitHub Actions

## Global Constraints

- 구현 기준점은 Contract v1.4 적용이 병합된 `origin/main` `0f7f626` 이후다.
- 현재 primary worktree의 수정된 report와 `.playwright-cli/`, `output/`, `/private/tmp/comins-data-table-v13`, 관련 stash를 변경하거나 삭제하지 않는다.
- 제품 소스, 공개 API, exports, CSS, Playground 동작과 package version `0.1.5`를 변경하지 않는다.
- 새 npm 의존성을 추가하지 않는다. `package.json`과 lockfile metadata 및 기존 Node/npm/tar 기능으로 구현한다.
- routine dependency에는 upstream source hash, 전체 license text hash, dependency-edge graph를 만들지 않는다.
- 자동 통과 목록은 `MIT`, `MIT-0`, `ISC`, `0BSD`, `BSD-2-Clause`, `BSD-3-Clause`, `Apache-2.0`으로 고정한다.
- `OFL-1.1`은 unmodified font, full license text, Reserved Font Name 보존, distribution boundary가 모두 확인될 때만 asset 검사에서 통과한다.
- 자동 목록 밖의 identifier, 누락·unknown metadata, compound expression, copyleft·source-available·proprietary·restrictive term은 수기 검토 대상으로 fail closed 한다.
- scoped approval은 실제 유지관리자 승인 전 생성하거나 추정하지 않는다. npm stage/publish 승인을 라이선스 승인으로 재사용하지 않는다.
- 라이선스 오류에는 component, exact version, SPDX identifier, use surface만 출력할 수 있다. 개인 연락처와 license 본문은 출력하지 않는다.
- public publish, tag, GitHub Release, provider 설정 변경, legacy npm remediation은 이 계획 범위 밖이다.

## Confirmed Baseline

- Governance PR 병합 후 Data Table PR #30에서 Contract v1.4 managed block과 instruction test가 이미 `origin/main`에 반영됐다.
- 현재 lockfile에는 package entry 181개, license metadata 누락 0개가 있다.
- 자동 목록 밖의 현재 metadata는 `MPL-2.0` 12개, `BlueOak-1.0.0` 1개, `CC0-1.0` 1개다. 모두 development-only이며 현재 npm runtime/package bundle에는 포함되지 않는다.
- `MPL-2.0`은 Governance의 copyleft 수기 검토 trigger에 해당한다. `BlueOak-1.0.0`과 `CC0-1.0`도 공통 자동 통과 목록 밖이므로 scoped review 결과 없이는 checker가 추정 통과시키지 않는다.
- npm artifact는 이미 `LICENSE`, `THIRD_PARTY_NOTICES.md`, package allow-list, bundled `node_modules` source/source-map 부재를 검사한다.
- Spoqa Han Sans Neo WOFF2 3개는 Playground repository asset이며 npm artifact에는 포함되지 않는다. 인접한 `LICENSE.SpoqaHanSans.txt`에 OFL-1.1 text와 Reserved Font Names가 존재한다.
- `THIRD_PARTY_NOTICES.md`는 immutable npm `0.1.0`~`0.1.4`의 Lucide/Feather legacy notice이며 현재 package에도 계속 포함한다.

## Selected Approach

1. **선택: clean v1.4 base에서 lean checker를 새로 작성한다.** 정책과 구현이 직접 대응하고 stale v1.3 evidence를 제거하기 쉽다.
2. **기각: v1.3 checker를 축소 수정한다.** 177개 evidence, archive/source hashes, approval schema가 v1.4의 routine-check 경계를 구조적으로 초과한다.
3. **기각: 기존 artifact checker만 사용한다.** exact package bundle은 확인하지만 lockfile license metadata와 repository-distributed font asset을 다루지 못한다.

### Task 2: Implement Routine Dependency and Scoped Approval Checks

**Files:**
- Create: `scripts/check-licenses.mjs`
- Test: `test/license-gates.node.mjs`

**Interfaces:**
- Consumes: `package.json`, lockfile v3 `packages`, optional `THIRD_PARTY_LICENSE_APPROVALS.json`.
- Produces: exit 0 with no output, review-required lines with exit 1, or constant structural failure with exit 1.

- [ ] **Step 1: Parse deterministic repository inputs**

Implement:

```js
const AUTOMATIC_LICENSES = new Set([
  'MIT',
  'MIT-0',
  'ISC',
  '0BSD',
  'BSD-2-Clause',
  'BSD-3-Clause',
  'Apache-2.0',
]);
```

Reject unsupported lockfile versions, missing `packages`, missing root `license`, missing dependency license metadata, non-string identifiers, unsafe artifact paths, and malformed approval records.

- [ ] **Step 2: Classify use surfaces without dependency graphs**

Derive only:

- `development-only-tooling` from lockfile `dev: true`;
- `peer-or-external-runtime` from root `peerDependencies`;
- `runtime` from root `dependencies` or `optionalDependencies`;
- `transitive-runtime` for remaining non-dev lock entries.

Do not store every transitive component in a repository inventory file.

- [ ] **Step 3: Implement review triggers**

Require scoped review when metadata is not in `AUTOMATIC_LICENSES`, is missing/unknown, contains a compound expression, or matches a restrictive/copyleft classification. The diagnostic format is:

```text
license-check: review required: lightningcss@1.32.0 (MPL-2.0; development-only-tooling)
```

Sort diagnostics by component and version for deterministic CI output.

- [ ] **Step 4: Implement the minimal approval shape**

Accept `THIRD_PARTY_LICENSE_APPROVALS.json` only with this exact top-level shape:

```json
{
  "schemaVersion": 1,
  "approvals": []
}
```

Each approval must contain:

```json
{
  "components": ["exact-package-name"],
  "version": "exact-version",
  "license": "exact-SPDX-identifier",
  "useSurface": "development-only-tooling",
  "distributed": false,
  "conditions": ["reviewed condition"],
  "rationale": "review rationale",
  "approvedBy": "maintainer",
  "reviewDate": "2026-07-29",
  "invalidatesOn": [
    "component",
    "version",
    "license",
    "use-surface",
    "distribution"
  ]
}
```

Validate real calendar dates and unique non-empty arrays. Do not accept hashes, source contacts, broad version ranges, repository-wide suppressions, or unknown properties.

- [ ] **Step 5: Keep approval absent until the maintainer gate**

Run:

```bash
node scripts/check-licenses.mjs
```

Expected: exit 1 with deterministic review-required lines for the current non-automatic license groups. Record the exact groups for Task 4; do not create the approval file yet.

- [ ] **Step 6: Verify fixture GREEN**

Run:

```bash
node --test test/license-gates.node.mjs
```

Expected: fixture tests pass, including explicit approved fixtures; only the real repository remains intentionally blocked when exercised without an approval record.

- [ ] **Step 7: Commit the checker**

```bash
git add scripts/check-licenses.mjs test/license-gates.node.mjs
git commit -m "feat: add lean dependency license gate"
```
