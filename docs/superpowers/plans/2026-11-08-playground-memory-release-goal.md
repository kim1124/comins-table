# 0.2.4 Playground 개선 및 릴리즈 목표 수정안

앱 Goal 도구는 본문 변경 기능을 제공하지 않으며 Codex 앱 UI 접근도 차단되어 있다. 아래는 사용자 승인에 따라 이 작업의 실행 기준으로 적용하는 수정 본문이다. 기존 앱 Goal을 완료로 바꿔 우회 교체하지 않는다.

```text
Main 기반 comins-table 0.2.4 정식 릴리즈·배포를 최종 목표로 유지한다. 기존 로컬 작업·Vue3·과거 메모리 FAIL과 원시 증거를 보존한다. 일반 배포 승인으로 메모리 기준 예외를 승인한 것으로 해석하지 않는다.

0. 먼저 완료된 SDK 메모리 해제 수정, releaseFocus API, Excel Table UI, React18/19 SSR 및 관련 테스트·문서를 선별해 커밋하고 Main 대상 PR을 생성한다. 조사 중 자료와 무관한 로컬 작업은 제외한다. 정확한 PR head의 필수 CI와 변경 범위를 검증하고 실패 원인을 수정한다. PR 생성·CI 성공을 수치 메모리 합격이나 출시 완료로 표현하지 않는다.
1. 기존 귀속 조사와 실제 Astra/high 리뷰를 재사용한다. 추가 SDK 보유 결함이 입증되지 않은 기존28FAIL을 다시 SDK 문제로 가정하지 않는다. 새 SDK 결함 증거가 없는 한 SDK를 수정하지 않는다.
2. Playground의 API 문서 데이터·파생 배열 반복 생성, Sidebar·CodeExample 불필요 렌더링을 후보로 검토한다. 원인·효과를 먼저 확인하고 동작을 유지하는 최소 개선만 적용한다. 언어별 데이터 캐시가 필요하면2개로 제한하고 순수 데이터만 보관한다. 컴포넌트 수명 밖에 DOM·React요소·이벤트·앱콜백을 저장하지 않는다. 기존 DocsShell memo/하이라이트 WeakMap을 중복 구현하지 않는다. 개선 근거가 없는 후보는 적용하지 않는다.
3. 실제 Playground 개발 빌드와 배포 빌드를 별도 실행한다. 소스·패키지·런타임·데이터·props·이동·viewport·포커스·GC·계측 조건을 고정하고 차이를 기록한다. 기존 개발 모드28FAIL을 배포 빌드 PASS로 소급 해제하지 않는다. production만으로 해결된다고 가정하지 않는다.
4. L1제품수명/L2활성기능/L3전체화면수치를 각각 판정한다. JSHeap·DOMNodes·리스너 각각2%이하, 고정warmup10, 독립새브라우저3회×300회,0/10/50/100/200/300 및 최종Unmount 체크포인트, 최초mounted/free기준과 중간FAIL을 유지한다. 수치 실행에는 cohort·WeakRef이력·snapshot·allocation 계측을 추가하지 않고 원시 이력은 브라우저 밖에 기록한다. 보유 진단은 별도 실행·양성/해제 대조로 유효성을 확인한다.
5. 각 후보는 재현→최소수정→관련회귀→통과시종료한다. 조사 회차는 가설1개·최대30분·신규브라우저실험2회이며 새 근거 없는 반복을 금지한다. 기능·언어전환·실제SPA수명은 보존한다. Playground공유렌더/라우팅 변경 후 관련spec과 전체E2E, 메모리계약 변경 후 focusedperf와 최종전체perf1회를 수행한다. 조건이 같은 기존 성공 증거는 재사용한다.
6. 개선 전후 효과와 잔여FAIL을 보고한 뒤 출시 gate의 처리 방법을 결정한다. 기준 변경·예외는 별도 명시승인을 받는다. 평균차감·기준재설정·워밍업증가·정적데이터삭제·React/V8비공개캐시조작·JIT비활성화로 FAIL을 지우지 않는다.
7. Excel·SSR 인수와 WebGPU20%미달 미채택을 유지한다. 출시 차단을 해소한 뒤0.2.4버전·릴리즈노트·정확한workflow산출물의기능/소비자/보안/라이선스/CI를 검증하고 OIDC staged publish, maintainer2FA, GitHubRelease, 공개registry무결성·provenance·소비검증까지 수행한다. 모든사후검증이완료된closed상태에서만 목표를완료한다.
```

## 진행 순서

- [ ] 완료분 커밋·PR·정확한 head CI 검증
- [ ] Playground 후보 효과 확인 및 근거 있는 최소 개선
- [ ] 개발·배포 실제 Playground 검증과 전후 비교
- [ ] 잔여 출시 gate 판정
- [ ] 정식 배포 및 사후 검증
