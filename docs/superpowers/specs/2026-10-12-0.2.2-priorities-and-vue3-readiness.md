# 0.2.2 우선순위 및 Vue 3 준비 상태

검토일: 2026-10-12 KST. 기준 main: `49f6790b320f4ce8038191f7865355730a90b093`.
사용자 요청에 따라 기능 우선순위를 정하고 Vue 3 전용 로컬 브랜치에서 소비자 검증을 진행했다.
이 문서는 합의된 릴리스 방향과 기존 검증 기록을 보관한다. 아래 초기 우선순위보다 후속 사용자 결정이 우선한다. XLSX 엔진·배포 방식·세부 API는 구현 전 설계 대상으로 남기며, 이 문서는 최종 구현 계획이나 신규 기능의 지원 완료 선언이 아니다.

## 최초 검토 당시 0.2.2 우선순위 (후속 결정으로 일부 대체)

| 우선순위 | 항목 | 완료 기준 |
| --- | --- | --- |
| P0 | 확인된 취약점 해소 및 파일 출력 안전성 | 현재 main의 npm audit은 개발 의존성을 포함해 0건이다. 기존 source-map-js 1.2.2 패치를 유지하고, 신규 XLSX 엔진의 정확한 버전·전이 의존성·라이선스·브라우저 번들을 검사한다. 문자열을 수식으로 자동 변환하지 않으며, 원본 데이터 변경 및 관리 열 충돌을 방지한다. 발견된 중대 취약점은 기능보다 먼저 처리한다. |
| P1 | XLSX Export | `.xlsx`, 단일 시트, 기본 스칼라 값, 열 순서·헤더·원본/표시 값 정책을 지원한다. Tree·Group은 기존 준비 함수와 `__rowId`, `__parentId`, `__depth`, `__groupId` 계약을 재사용한다. 실제 파일을 독립적으로 다시 읽어 셀 값과 타입을 확인하고, 브라우저 다운로드 및 자원 한도를 검증한다. |
| P2 | 대량 CSV Playground 개선 | 가져온 행 전체를 한 번에 DOM으로 렌더링하지 않으며 전체 CSV를 무제한 미리보기로 출력하지 않는다. 기존 입력 한도·검증 완료 후 교체·실패 시 데이터 유지 계약을 보존한다. |
| P3 | 안정화와 예제·문서 | main에 반영된 하단 Context Menu 위치 수정과 상호작용 테스트 보정을 포함한다. XLSX의 한·영 가이드, 예제, 제한사항, 파일 검증 사례를 제공한다. |

0.2.1의 README 간소화, CSV Import, Tree/Group CSV·JSON Export, React Tree 슬롯은 완료된 기능으로 유지한다.
0.2.2의 신규 대표 기능은 XLSX Export로 정한다. Vue 3 구현은 별도 0.3.0 브랜치에서 진행한다.

후속 기능 순서는 XLSX Import → PDF Export → 추가 테이블 편의 기능으로 둔다. PDF Import는 현재 릴리스 계획에서 제외한다.
XLSX Import에는 시트 선택·수식 결과·날짜·압축 해제 후 입력 한도·일반 행 매핑 계약이 필요하다.
PDF Export에는 한글 폰트·페이지 분할·반복 헤더·넓은 테이블 출력 정책이 필요하다.

### 구현 전 남은 설계 결정

- XLSX 변환 라이브러리와 정확한 버전, 기본 포함/선택 설치, 별도 진입점 여부.
- 지원 셀 타입과 날짜·큰 정수·객체·빈 값 처리, 행/셀/파일 크기 한도.
- Core는 데이터·열·구조 메타데이터를 준비하고, 프레임워크 중립 변환 모듈은 XLSX 파일을 생성하며, Browser는 다운로드를 담당한다. Core에 React나 DOM 의존성을 추가하지 않는다.
- 파일 출력 안전성은 신규 기능의 요구사항이다. 현재 CSV Core가 수식 문자를 보존하는 문서화된 계약을 확인된 취약점으로 분류하지 않는다.

## 후속 사용자 결정: 0.2.2 범위와 렌더링 API 전환

2026-10-12 대화에서 확정한 방향이다. 위 최초 검토의 XLSX Export 전용 범위와 Tree 포함 방침은 아래 결정으로 대체한다.

- Excel/CSV Import 및 Export를 일반 행 데이터 대상으로 다룬다. 신규 파일 입출력 범위에 Tree 구조 지원을 포함하지 않는다. 기존 0.2.1 Tree/Group CSV·JSON 보조 API를 제거한다는 뜻은 아니다.
- 값 목록 선택 필터를 검토 범위에 포함한다. 사용자 배지·아이콘·라벨뿐 아니라 필터 UI의 HTML 구조 커스터마이징을 고려한다. 기존 클래스·스타일 API의 실효성도 예제로 검증한다.
- 렌더링 API 명칭 정리를 0.2.2에 포함한다. 사용자 정의 UI의 표준 최종 진입점은 `render`로 통일하며, 기존 공개 속성은 현재 버전에서 유지한다. 구체적인 신규 경로·전환 매핑·반환값 규칙은 [렌더링 API 대응표](./2026-10-12-rendering-api-migration-design.md)에 정리한다.
- 셀 툴팁은 사용자 승인에 따라 `cell.tooltip.render`로 배지·아이콘·사용자 컴포넌트 콘텐츠를 실제 표시하도록 확장한다. 기존 문자열 툴팁은 유지한다.
- 기존 속성의 실제 제거는 다음 메이저 릴리스에서 수행한다. 현재 0.x 계열에서 다음 메이저는 1.0.0이며, Vue 3 대상 0.3.0에서 자동으로 제거하지 않는다. 제거 일정은 별도 릴리스 일정이며 아직 정하지 않았다.

### 여러 프레임워크에 적용할 계약

- Core는 데이터, 상태 전이, 필터 판정 및 프레임워크 중립 입력 정보를 소유한다. ReactNode, Vue VNode, Svelte Snippet, Angular TemplateRef, DOM 생성 코드를 Core에 추가하지 않는다.
- 공통화 대상은 렌더링 영역의 의미, 공개 설정 경로의 명명 원칙, 입력 데이터와 상태, 기본 콘텐츠 및 사용자 콘텐츠의 처리 규칙이다. 모든 프레임워크에 React JSX 반환 함수 타입을 강제하지 않는다.
- React는 렌더링 콜백에서 JSX를 반환하고, Vue는 렌더 함수·scoped slot, Svelte는 snippet, Angular는 template, Solid는 고유 JSX 반응성에 맞게 연결할 수 있도록 어댑터 경계를 유지한다. Vanilla DOM 어댑터도 mount/update/dispose와 이벤트 해제를 어댑터에서 담당하는 구조를 고려한다.
- 위 항목은 확장 설계의 고려 대상이다. Vue 외 어댑터의 구현, 출시 순서, SSR 및 전체 기능 동등성 지원을 약속하지 않는다. `render` 의미를 통일하더라도 템플릿 문법과 실행 생명주기는 프레임워크별로 설명한다.
- 기존 `renderer`를 컴포넌트 타입이라는 새 의미로 바꾸지 않는다. 현재 일반 콜백 계약을 유지하고 신규 표준과 호환되게 연결한다. 컴포넌트 타입과 일반 콜백을 함수 모양만으로 추측하지 않는다.
- 콘텐츠 교체와 외부 `td`/`tr`/`th` 태그 교체를 구분한다. 명칭 정리만으로 외부 구조 교체 기능을 추가했다고 선언하지 않는다. `format`, `aggregate`, `label`, 스타일 속성의 기존 의미를 보존한다.

### 전환 문서와 검증 완료 조건

신규 API 구현과 함께 아래 문서를 동일한 계약으로 갱신한다. 구현 전 현재 사용자 가이드에 미지원 API를 사용 가능한 기능으로 기재하지 않는다.

1. `docs/user/`와 `docs/ko/`: 셀, 헤더, Tree, Group, Summary, 상세 행, 툴팁, 로딩/빈 상태 및 신규 필터의 영향받는 가이드를 함께 갱신한다. 기존 이름, 새 경로, 지원 시작 버전, 폐기 예정 여부, 제거 대상 메이저, 전환 전후 예제를 제공한다.
2. 마이그레이션 가이드: 이전/신규 이름 동시 지정, 미지정·`null`·`undefined` 반환, 기본 콘텐츠, 콜백/컴포넌트 호출, 스타일 우선순위, 교체 가능한 DOM 범위를 명시한다. 기존 API의 동작 차이를 단순 이름 변경 과정에서 조용히 바꾸지 않는다.
3. 공개 TypeScript/JSDoc: 새 표준을 안내하고, 대응 API가 구현된 기존 속성에 대체 경로와 제거 메이저를 포함한 `@deprecated` 설명을 추가한다. 현재 `cell.tooltip`의 ReactNode 허용 타입과 문자열만 표시하는 구현 차이는 기존 동작을 보존하면서 새 객체형 커스텀 툴팁으로 해소한다.
4. Playground의 한·영 API/속성 설명과 예제, 기능 manifest, CHANGELOG를 갱신한다. README는 짧은 전환 안내와 언어별 마이그레이션 링크만 제공해 기존 간소화 방침을 유지한다. 홈페이지에 노출되는 문서도 릴리스 시점의 실제 지원 내용과 일치시킨다.
5. 타입·회귀 테스트로 기존 사용 코드와 신규 사용 코드의 동작, 커스텀 클래스와 콘텐츠 및 구조 변경 사례를 확인한다. Core의 프레임워크 비의존성을 유지하고, 실제 제공하는 어댑터에 한해 소비자 검증을 수행한다. 아직 구현하지 않은 어댑터를 검증 완료로 보고하지 않는다.
6. 다음 메이저에서 기존 속성을 제거할 때 타입·런타임·문서·예제·패키지 소비자를 함께 갱신한다. 이전 문서는 적용 버전을 명시하고, 현재 버전 안내에서 더 이상 지원되는 것으로 남기지 않는다.

## Vue 3 브랜치와 검증

브랜치: `codex-0.3.0-vue3`, 생성 기준은 위 main 커밋이다. 원격 브랜치·PR·배포는 생성하지 않았다.
첫 단계는 배포된 Comins Vue Table이 아닌 **Vue + 공개 Core 소비자 호환성 검증**이다.

실행:

```sh
npm run build
mkdir -p .local/vue3-probe
npm pack --offline --ignore-scripts --json --pack-destination .local/vue3-probe
node test/vue-core-consumer.mjs .local/vue3-probe/comins-table-0.2.1.tgz
```

위 runner는 신뢰된 로컬 tarball만 입력받는다. 임시 소비자에서 Vue 3.5.43을 정확히 지정해 설치하고, 설치 스크립트를 실행하지 않는다. 저장소의 package.json 및 lockfile은 변경하지 않는다. 네트워크 설치와 로컬 브라우저 실행 권한이 필요하다. 테스트 종료 시 runner가 만든 임시 소비자만 제거한다.

| Vue 3.5.43 소비자 설치 의존성 감사·라이선스 목록 | 취약점 0건, 허용 라이선스 목록 통과 |

React 제외 검증은 임시 설치에서 React 폴더를 이동한 의도적인 격리 실험이다. 일반 설치가 React 없이 완료됐다는 의미가 아니다.
예제의 간단한 Vue HTML table은 Core 결과 표시를 위한 테스트 fixture다. CominsTable의 Vue 포팅이나 지원 완료를 의미하지 않는다.

## Vue 3 다음 작업 순서

1. **패키지·의존성 경계**: 동일 패키지 Vue 진입점 또는 독립 어댑터/Core 패키지 구성을 결정한다. React peer 및 React 아이콘의 설치 경로까지 포함한다. Browser와 내부 상태 조정/projection의 공유 API 범위도 함께 정한다.
2. **최소 Vue 어댑터 계약**: 애플리케이션 소유 data, props/events, 공개 메서드, 셀·Tree 슬롯을 확정한다. Vue 반응성에 맞춰 Core의 참조 보존 및 통지 순서를 연결한다.
3. **기본 Table 구현과 타입 검사**: 실제 Vue Table 컴포넌트, Vue 렌더러 타입, SFC 또는 TSX 빌드·선언 검증을 추가한다.
4. **UI 기능 확장**: Tree/Group, 포인터·키보드, 가상화·측정, Viewport 요청 취소, clipboard, 세부 영역 focus와 unmount 해제를 구현·검증한다.
5. **지원 선언 게이트**: Vue 전용 npm 소비자, 문서 예제, 실제 브라우저/E2E/성능, React 18/19 회귀를 같은 최종 패키지로 확인한다.

현재는 1단계 설계에 필요한 Core/Vue 소비자 실증이 완료된 상태다. 실제 Comins Vue UI·SFC·SSR·전체 기능 동등성은 아직 검증하지 않았다.
