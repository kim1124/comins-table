# Comins Table 0.1.10 Tree 드래그, 자동 높이 및 Viewport Datasource 구현 계획

- 작성일: 2026-09-07
- 상태: 로컬 구현 및 최종 게이트 완료 / 원격 미반영
- 목표 버전: `comins-table@0.1.10`
- 조사 기준: 로컬 `main`, `1ff6d0d`, 패키지 버전 `0.1.9`
- 공통 정책: Comins Contract v1.8
- 구현 브랜치: `codex-0-1-10-tree-viewport`
- 사용자 구현 승인 후 로컬 제품 코드·문서·버전을 갱신한다. 원격 쓰기와 배포는 포함하지 않는다.

## 1. 목표와 확정된 방향

0.1.10은 다음 세 기능을 제공한다.

1. Tree Grid의 모든 깊이에서 형제 Row 순서 변경. 부모 변경은 애플리케이션이 옵션으로 허용한다.
2. 일반 업무 Row의 고정 높이, Row별 지정 높이, 콘텐츠 자동 높이와 이에 맞는 가변 높이 가상화.
3. 전체 건수를 아는 구간 요청형 Viewport Datasource와 자동 높이의 결합.

높이 정책과 기능 활성화는 props로 선택하고, 선택된 자동 모드의 측정·재측정·배치·스크롤 보정은 Table이 처리한다. 사용자가 Renderer별 높이를 계산하거나 Observer를 직접 연결할 필요가 없어야 한다.

**Viewport + 자동 높이는 이번 버전의 필수 완료 항목**이다. 결합 검증이 실패하면 원인을 해결하거나 변경된 범위를 다시 협의하며, 고정 높이만 제공하고 세 기능을 완료했다고 보고하지 않는다.

사용자가 승인한 제품 방향과 이를 구현하기 위한 아래 API·내부 구조·검증 명세를 구분한다. 문서에 제시한 신규 API는 구현할 계약이며, 현재 배포된 API가 아니다. 내부 함수 분리와 파일명은 동작 계약을 보존하는 범위에서 조정할 수 있다.

## 2. 현재 구현에서 확인한 사실

| 근거 | 확인 사항 | 구현 시 의미 |
| --- | --- | --- |
| `src/tree.ts` | `{ item, expand?, children? }` 중첩 모델, 전역 ID 검사, preorder flatten, 형제별 정렬 | 중첩 모델과 ID를 유지하는 전용 이동 연산 필요 |
| `src/index.tsx`의 `CominsTreeTableInner` | 보이는 item을 내부 Table에 전달하고 값 변경을 원본 Tree에 반영. Tree draggable은 차단 | flat 배열 이동을 그대로 활성화하면 안 됨 |
| `src/index.tsx`의 Row Drag lifecycle | 시작 전 취소, target 변경 통지, 종료 결과와 listener 정리 | 수명주기 재사용, Tree 목적지 정보 추가 |
| `src/virtual-layout.ts` | 누적 높이 인덱스, 논리/물리 스크롤 변환, ID 기반 anchor | CSR 자동 높이에 기존 연산 활용 가능 |
| `src/index.tsx`의 mixed projection | 현재는 펼쳐진 Detail이 있을 때만 가변 높이 경로 사용 | 일반 업무 Row 높이를 독립적으로 모델링해야 함 |
| `src/virtual-layout.ts`의 측정 캐시 | Row ID와 폭을 사용하고 현재 데이터에서 사라진 ID는 제거 | Viewport 캐시 퇴출과 데이터 삭제를 구분해야 함 |
| `src/index.tsx`, `styles.css` | 일반 Row/Cell 높이와 가상화 계산은 공통 `rowHeight`에 의존 | Renderer CSS 높이만 변경하는 방식은 사용할 수 없음 |

| `src/core.ts` | rows, rowIds, 정렬·선택·집계가 dense 업무 배열을 전제로 함 | 미수신 placeholder를 일반 업무 Row로 전달하면 안 됨 |
| `src/index.tsx`의 Cell 렌더 | 표시하도록 설정된 모든 Column을 각 렌더 Row에 출력 | 자동 높이에서도 이 정책을 유지하고 별도 수평 가상화를 추가하지 않음 |

선행 검토에서 `test/tree-core.test.ts`, `test/virtual-layout.test.ts`의 17개 테스트가 통과했다. 기존 함수의 별도 수치 확인에서는 화면 위 Row 높이가 204px 증가할 때 같은 Row와 내부 12px 위치를 유지하는 보정을 확인했다. 두 결과는 기존 기반의 증거이며 신규 UI·Viewport·성능 통과 증거가 아니다.

## 3. 범위와 호환성

### 포함

- Tree subtree 이동 pure helper, 드래그 UI, 부모 변경 제한, controlled callback, 목적지 표시와 취소/포커스 처리.
- 일반 Row별 지정 높이 및 자동 높이, 기존 Detail과의 높이 합산, 동적 Renderer 크기 변경.
- Flat, Grouped leaf, Tree 업무 Row의 높이 처리. 합성 Group Row, Header, Summary는 기존 높이 정책 유지.
- Viewport의 절대 인덱스, 미수신 구간, 제한된 데이터 캐시, 요청 취소·오류·재시도, 제한된 높이 정보.
- Viewport 고정/자동 높이, Pinning·Cell renderer·로딩된 Row 선택과 Cell 편집의 연동.
- 기존 공개 API, 영문·한글 문서, Feature Manifest, Playground와 검증의 정합성.
- 구현 완료 단계의 package/lockfile `0.1.10`, CHANGELOG와 패키지 산출물 검증.

### 이번 기능에 포함하지 않는 확장

- 서버 push/WebSocket 구독, 전체 서버 Row Model, remote Tree 및 서버 Grouping/Pivot.
- Tree의 Cross-Table 이동, 여러 Tree 노드의 동시 드래그, Tree Row 단위 clipboard.
- Viewport의 Tree/Row Grouping/Row Detail 결합, 서버 집계 UI, 미수신 범위를 자동 다운로드하는 복사·선택·내보내기.
- 새로운 수평 Column 가상화, 일반 Cell 병합, 별도 외부 store 프레임워크, 신규 런타임 의존성.
- 브라우저 지원 범위 확대, SSR, 원격 push·PR·merge·배포 자동 실행.

위 제한은 선택한 세 기능이 모든 기존 기능 조합까지 자동으로 확장되는 것을 방지한다. 기존 CSR의 지원 조합을 제거하거나 변경하는 권한으로 해석하지 않는다.

## 4. Tree Grid Row 드래그

### 4.1 공개 설정과 데이터 계약

- Tree 전용 `treeRowDrag?: { allowReparent?: boolean; canDrop?: (context) => boolean }`를 추가한다.
- 설정이 없으면 현재처럼 Tree 드래그를 비활성화한다. 설정한 경우 `allowReparent` 기본값은 `false`다.
- `rowProps.draggable`은 Tree에서도 Row별 source 허용 조건으로 사용할 수 있도록 확장한다. `rowProps.disabled`와 `onChangeData` 유무도 함께 확인한다.
- `allowReparent: false`는 **모든 깊이의 동일 부모 내 재배치**다. 루트끼리의 재배치도 같은 규칙이다. UI의 1 Depth는 내부 `depth: 0`에 해당한다.
- `allowReparent: true`이면 다른 부모의 자식 또는 루트로 이동할 수 있다. `canDrop`은 허용 범위를 더 좁힐 수 있지만 순환 금지 등 구조 규칙을 해제할 수 없다.
- source 노드와 접힌 descendant를 포함한 전체 subtree가 하나의 이동 단위다. `item`, ID와 각 노드의 명시적 `expand` 값을 보존한다.
- `getRowId`는 접힌 노드를 포함하여 안정적이고 전역적으로 유일해야 한다. 현재 위치에 따른 ID 생성은 이동 계약에 사용할 수 없다.
- 기존 Tree `data`와 `onChangeData(nextTree)`를 유지한다. 애플리케이션의 원본 배열·노드를 변경하지 않고 영향받은 조상 경로만 새 객체로 만든다.

### 4.2 이동 연산과 목적지

- `moveCominsTreeNode` pure helper와 관련 타입을 `src/tree.ts`에 추가하고 기존 Tree helper와 같은 root export 경로에 공개한다. 새 subpath는 만들지 않는다.
- UI는 `before`, `after`, `inside` 의도를 구분한다. 내부 목적지는 안정적인 `parentId`와 `beforeRowId`로 정규화하며 `null`은 루트 또는 해당 형제 배열의 끝을 뜻한다.
- source를 제거한 뒤 목적지 ID를 다시 찾아 삽입한다. 같은 배열 내 아래로 이동할 때의 인덱스 이동을 별도로 보정해야 한다.
- `after`는 목적지 노드의 전체 subtree 뒤다. source와 자신의 자손을 목적지로 하는 이동, 존재하지 않는 ID, 동일 위치, 중복 ID를 검증한다.
- 비어 있는 자식 배열이나 기존 leaf에도 `inside`를 허용하되 애플리케이션이 `canDrop`으로 제한할 수 있다. 마지막 자식이 이동한 원래 부모는 업무 노드로 남는다.
- 현재 Summary는 leaf만 집계하므로 부모/leaf 전환 시 집계 대상 변화도 테스트·문서에 포함한다. 가짜 부모나 placeholder 업무 데이터를 생성하지 않는다.

### 4.3 UI와 수명주기

- Tree 드래그는 명시적인 handle에서 시작한다. Expander, Cell selection, built-in component 및 renderer 내부 조작과 충돌하지 않게 한다.
- 드래그 중에는 원본 Tree를 재배치하지 않는다. 목적지 선, 부모 강조, 허용/거부 상태만 표시한다.
- 접힌 부모도 `inside` 목적지로 사용할 수 있다. hover만으로 controlled expansion을 바꾸지 않는다. Drop 이후에도 expansion 정책을 보존하며 필요한 포커스는 대상 부모로 이동한다.
- 일반 목적지는 보이는 Row의 실제 bounds로 계산한다. 가변 높이에서 `index * rowHeight` 또는 고정 크기의 Row 중앙을 사용하지 않는다.
- Table 내부 edge auto-scroll을 지원하고 스크롤·재측정 후 목적지를 다시 계산한다. Table instance와 실제 Row ID를 확인하여 재활용된 DOM을 오래된 목적지로 사용하지 않는다.
- 정렬 모델이 활성화된 동안 Tree 수동 이동을 차단한다. 정렬 해제 후 원본 형제 순서로 이동할 수 있다.
- 데이터 revision/참조의 외부 교체, source·target 삭제, 정책 변경, unmount, Escape, pointer cancel, blur에서 gesture를 정리한다.
- `onBeforeRowDrag`, `onRowDrag`, `onAfterDragRow`의 기존 의미를 유지하고 Tree parent/path/position 정보를 선택적 구조로 추가한다. 기존 result/reason을 불필요하게 확대하지 않는다.
- 시작 전 취소에는 시작된 gesture의 종료 callback을 만들지 않는다. 시작된 gesture는 성공·거부·취소 중 정확히 한 번 종료한다.
- Drop 성공 시 `onChangeData`를 한 번 호출한다. controlled 소비자가 반영하지 않은 결과를 내부 영구 상태로 저장하지 않는다.
- handle을 키보드로 사용할 수 있게 한다. Space로 이동 모드를 시작하고 위/아래 방향키로 보이는 목적지를 순회한다. 부모 변경 허용 시 오른쪽 방향키는 선택한 목적지의 자식으로, 왼쪽 방향키는 현재 부모 밖으로의 이동 의도를 선택한다. Enter로 확정하고 Escape로 취소하며 목적지·거부·결과를 알린다. pointer와 동일한 validation 연산을 사용한다.

## 5. 일반 Row 높이와 가변 가상화

### 5.1 공개 API

기존 `rowHeight?: number`를 유지하고 다음 선택적 API를 추가한다.

```ts
type CominsRowHeight = number | "auto";
type CominsRowHeightParams<TData> = { row: CominsEventRow<TData> };

getRowHeight?: (params: CominsRowHeightParams<TData>) => CominsRowHeight | undefined;
estimatedRowHeight?: number;
```

- `getRowHeight` 미지정 또는 `undefined` 반환은 기존 공통 `rowHeight`를 사용한다.
- 양의 유한 숫자는 해당 Row의 지정 높이다. `"auto"`는 콘텐츠 높이를 측정한다.
- `estimatedRowHeight`는 미측정 Row의 임시 높이이며 실제 높이 제한이 아니다. 기본값은 유효한 `rowHeight`다.
- 0, 음수, NaN, Infinity 등은 기존 유효한 기본 높이로 정규화한다. 측정 불가능한 숨김 요소의 0px 결과로 기존 양의 높이를 덮어쓰지 않는다.
- 일반 Row 전체의 자동 설정은 `getRowHeight={() => "auto"}` 한 번으로 표현한다. Renderer별 수치 입력이나 별도 측정 hook을 요구하지 않는다.
- 비가상 모드도 같은 높이 정책과 CSS를 사용한다. 자동 높이를 이유로 기존 `virtualized` 기본값을 변경하지 않는다.
- 높이를 결정하는 권한은 위 API에 둔다. 가상 모드에서 `rowProps.style.height`나 Cell CSS만으로 논리 높이를 변경하는 계약은 추가하지 않는다.

### 5.2 측정과 레이아웃

- `src/row-height.ts`에 높이 정규화, 측정 identity, cache invalidation을 분리한다. Table 전체 구조를 재작성하지 않는다.
- 자동 Row는 자연스러운 콘텐츠 높이를 측정할 수 있도록 일반 Row/Cell의 고정 높이 적용을 선택적으로 해제한다. 측정값을 다시 최소 높이로 강제하여 Row가 줄어들지 않는 순환을 만들지 않는다.
- 모든 표시 Column 중 가장 높은 콘텐츠와 실제 padding/border가 Row 높이에 반영되어야 한다. 가로 스크롤만으로 측정 Column 집합이 달라지지 않아야 한다.
- 기존 값 텍스트의 줄바꿈 정책을 전체 변경하지 않는다. Renderer의 일반 flow 콘텐츠와 명시적으로 줄바꿈을 설정한 Cell을 자동 측정한다.
- Portal, absolute-positioned overlay, transform만의 시각적 확대는 Row의 자연 높이로 추론하지 않는다. 내부 스크롤을 선택한 renderer는 해당 컨테이너의 높이가 측정 대상이다.
- 하나의 Table 수준 Observer가 현재 mount된 자동 Row를 관찰한다. 제거·재사용된 요소는 관찰 해제 및 ID 재연결을 수행한다.
- 콘텐츠 증가와 감소, 이미지·폰트 로딩, 비동기 renderer, Column resize/visibility, theme·density, data 교체를 재측정에 반영한다.
- cache key는 최소한 Row ID, 데이터 내용 revision/참조, 표시 Column과 폭의 layout revision을 구분한다. Table 전체 폭만 같다고 과거 측정값을 재사용하지 않는다.
- 같은 layout revision에서의 reorder는 측정값을 보존한다. 폭·스타일이 바뀐 offscreen Row는 stale 측정값을 확정값으로 취급하지 않는다.
- Observer callback은 commit된 snapshot만 읽는다. Suspense로 폐기된 render, 오래된 observer entry, DOM 재사용에 따른 ID 변경을 배제한다.
- 관찰 결과를 한 번에 수집하고 실제 높이 변화만 반영한다. 의미 없는 소수점 반복 갱신을 제거하며 매 entry마다 전체 projection을 재생성하지 않는다.

### 5.3 높이 인덱스와 anchor

- 업무 Row 높이와 Detail 높이를 분리한다. Slot 높이는 `업무 Row 높이 + 펼쳐진 Detail 높이`이며 합성 Group 높이는 별도다.
- 일반 auto/variable Row가 존재하면 Detail 없이도 가변 높이 경로를 사용한다. 모든 Row가 공통 고정 높이면 기존 산술 경로를 유지한다.
- CSR의 누적 높이·offset 검색·개별 측정 갱신은 기존 인덱스를 활용한다. 조회/갱신은 로그 비용을 유지하고 측정마다 전체 Row를 다시 순회하지 않는다.
- 현재 보이는 Row ID와 내부 offset으로 anchor를 잡고 높이 변화 후 같은 위치를 복구한다. Row 삭제 시 기존 이전/다음 생존 Row fallback을 사용한다.
- Row 자체가 작아진 경우 내부 offset을 새 높이로 clamp한다. 콘텐츠 축소나 dataset 삭제처럼 동일 위치가 존재하지 않는 상황을 무조건 같은 pixel로 고정하지 않는다.
- 기존 논리/물리 높이 제한과 anchor transaction을 유지한다. 스크롤 상한을 넘는 데이터에서도 physical scrollTop만 보존하지 않는다.
- wheel·touch·scrollbar 조작과 보정이 서로 싸우지 않도록 입력 상태를 추적한다. 측정 수집과 보정 적용 시점을 구분하고 읽는 위치 보존을 우선한다.

## 6. Viewport Datasource

### 6.1 데이터 소유권과 공개 경계

- 전체 건수를 알고 임의의 연속 인덱스 구간을 요청할 수 있는 datasource를 대상으로 한다. count를 아직 모르면 애플리케이션이 먼저 조회한 후 모드를 활성화한다.
- 업무 데이터 입력은 계속 `data` 하나다. 새 `CominsViewportTableProps<TData>` 분기에서만 `data`를 구간 정보를 가진 controlled snapshot으로 받는다. 기존 Flat 배열과 Tree node 배열 타입은 그대로 유지한다.
- snapshot은 `revision`, `rowCount`, 로딩된 blocks 및 bounded 구간 상태를 표현한다. block은 절대 `startIndex`와 실제 `rows`를 가진다. 전체 건수만큼 빈 객체나 undefined 배열을 만들지 않는다.
- `viewportDatasource` 설정이 기대하는 dataset revision과 snapshot revision을 대조한다. 오래된 snapshot은 새 쿼리 결과로 렌더링하지 않는다.
- `onViewportRequest`는 절대 시작/끝 인덱스, dataset revision, request ID, `AbortSignal`과 현재 보존해야 하는 구간을 받는다. 인덱스 범위는 일관되게 `[startIndex, endIndex)`다.
- 애플리케이션이 통신을 수행하고 응답을 controlled snapshot에 반영한다. Table은 임의 URL에 접근하거나 HTTP/WebSocket 정책을 소유하지 않는다.
- 기존 Lazy Load처럼 callback 반환값 자체를 업무 데이터로 저장하지 않는다. Promise는 요청 작업의 수명 관리에 사용한다.
- `createCominsViewportData` 및 `reduceCominsViewportData` pure helper를 `src/viewport-data.ts`와 root export에 제공한다. request/success/error/cancel/reset/loaded-row patch와 캐시 제한을 같은 규칙으로 처리한다.
- 공식 예제는 함수형 state 갱신으로 helper를 호출한다. 서로 다른 구간의 비동기 응답이 동일한 오래된 snapshot을 각각 덮어쓰지 않게 한다.
- 로딩 시작·완료·실패·취소 상태는 request token과 함께 helper에 반영한다. 완료 시 callback의 signal도 확인하며, reducer는 현재 revision과 해당 block의 최신 request token이 맞는 응답만 수용한다. 변경되지 않은 block과 업무 Row 참조를 보존한다.
- `onChangeData`는 해당 prop branch의 다음 snapshot을 전달한다. Cell 편집은 로딩된 Row를 ID로 patch하고 다른 block·구간 상태를 보존한다. 이것이 서버 저장을 의미하지는 않는다.
- 사용자 store와 네트워크 코드는 애플리케이션 소유로 남는다. 별도 외부 store adapter나 새 런타임 의존성을 도입하지 않는다.
- 협의 확정: 기본 사용법은 `useCominsViewport` hook이 rowCount, queryKey, getRows를 받아 애플리케이션 쪽 controlled snapshot과 Table props를 연결한다. snapshot/reducer는 고급 제어용으로도 제공하며 Table 내부에 별도 영구 업무 데이터 원본을 만들지 않는다.
- 협의 확정: 로딩된 Cell 편집과 붙여넣기는 유지한다. 서버 저장·미저장 변경의 보존은 애플리케이션 책임이며, hook의 변경 callback과 응답 변환을 통해 연동한다. 편집 이후 시작된 요청인지 확인하고, 같은 구간의 이전 조회가 최신 편집을 덮지 않도록 변경 세대를 검사한다.
- Promise 완료를 즉시 controlled props 반영 완료로 간주하지 않는다. hook은 응답 상태와 데이터를 한 state 갱신으로 반영하며 저수준 사용자는 명시적 success/error 상태로 완료를 알린다.

### 6.2 요청·캐시 수명

- 설계 기본값은 block당 100 Row, 데이터 cache 12 block, 동시 요청 2개로 둔다. 수치는 성능 검증으로 조정할 수 있는 기술 기본값이며 사용자 입력은 유효한 양의 정수로 정규화한다.
- 화면과 overscan에서 필요한 block을 계산하고 이미 loaded/in-flight인 동일 요청을 중복 실행하지 않는다. 렌더에 필요한 Row 수는 request block 크기와 분리한다.
- 현재 구간을 먼저 요청하고 주변 구간은 남은 예산으로 prefetch한다. 먼 곳으로 이동하면 오래된 prefetch를 취소하고 최신 화면 요청을 우선한다.
- 요청 상태는 missing → loading → loaded/error다. aborted 또는 revision이 지난 응답은 loaded로 반영하지 않는다.
- 데이터·request·error metadata가 모두 한도 없이 누적되지 않아야 한다. 현재 화면과 in-flight block을 우선 보존하고 나머지는 최근 사용 순서에 따라 퇴출한다.
- 화면 자체가 설정한 cache 한도보다 큰 경우 현재 렌더 구간과 허용된 in-flight 구간까지 effective 한도를 올린다. 이를 문서화하고 `max(설정 한도, 현재 필수 구간) + 요청 여유분`의 계산 가능한 상한으로 검증한다.
- request ID는 remount와 dataset 교체를 구분할 수 있어야 한다. 같은 block에 대한 오래된 응답이 새 응답을 덮어쓰지 않게 한다.
- 오류는 해당 구간의 상태와 재시도 UI로 표시한다. 자동 무한 retry를 하지 않으며 다른 성공 구간을 지우지 않는다. callback이 성공했지만 필요한 Row가 반영되지 않은 경우 재요청 폭주를 막고 불완전 응답을 식별한다.
- rowCount 감소, 검색·정렬 조건 변경, datasource 교체는 revision을 갱신하는 reset이다. 기존 요청·block·높이 정보를 무효화하고 새로운 시작 위치로 이동한다. 같은 revision 안에서는 순서와 count를 안정적으로 유지한다.
- 응답의 범위·길이·revision·유한 정수 인덱스와 cache 내 중복 Row ID를 검증한다. 아직 받지 않은 전역 데이터의 ID 유일성은 서버/애플리케이션 계약이며 클라이언트가 검증했다고 주장하지 않는다.

### 6.3 렌더링과 기존 기능 연결

- `src/viewport-layout.ts`와 Table adapter를 통해 절대 dataset 인덱스와 로딩된 cache 위치를 분리한다. 기존 dense core에 placeholder 업무 Row를 넣지 않는다.
- 미수신 구간은 viewport에 필요한 수만큼 skeleton을 출력한다. placeholder에는 업무 `getRowId`, renderer, formatter, selection, clipboard, edit callback을 호출하지 않는다.
- Viewport Row/Cell callback의 `row.dataIndex` 및 Row `index`는 절대 dataset 위치를 뜻한다. window 내 위치는 private 정보다. CSR의 기존 의미는 변경하지 않는다.
- Viewport의 `getRowId`는 필수다. Row 선택은 ID로 보존하며 cache 퇴출만으로 선택을 다른 Row에 이전하지 않는다. 전체 dataset revision 변경 시 선택을 초기화한다.
- Cell/range 선택은 로딩된 연속 구간에서만 구성한다. cache에서 사라진 Cell/range는 정리하고, 로딩된 범위 바깥을 자동으로 다운로드하지 않는다.
- 복사/붙여넣기는 필요한 모든 Cell이 로딩된 경우에만 원자적으로 처리한다. 구간에 구멍이 있으면 일부만 조용히 처리하지 않는다. 내보내기는 계속 애플리케이션이 helper에 전달한 Row만 대상으로 한다.
- `setSelectedRow(s)`는 Viewport에서 절대 인덱스를 사용하고 미수신 Row는 선택하지 않는다. `setMoveTargetRow`와 Tree/Group 전용 Ref는 해당 모드에서 안전하게 no-op한다.
- Viewport에서는 자체 Header 정렬 UI·sort Ref, Column Filtering, 자동 Summary 집계를 활성화하지 않는다. 애플리케이션의 외부 쿼리 UI가 revision과 결과 순서를 소유한다.
- 위 외부 쿼리 UI 범위는 협의 확정 사항이다. queryKey 변경 시 요청·캐시·선택·스크롤을 새 dataset 기준으로 초기화한다.
- Pinning, Column resize/layout, Header, 현재 로딩된 Cell component·renderer는 기존 구조를 활용한다. 범위가 바뀔 때 focus가 재활용된 다른 업무 Row로 옮겨가지 않게 한다.

## 7. Viewport + 자동 높이 결합

### 7.1 추정과 측정의 경계

- 미수신 Row의 높이는 `estimatedRowHeight` 또는 기본 `rowHeight`로 추정한다. 해당 업무 데이터가 없을 때 `getRowHeight`를 가짜 Row로 호출하지 않는다.
- 수신된 Row는 지정 높이 또는 자동 측정값을 적용한다. skeleton → 실제 Row 전환도 같은 anchor 보정을 거친다.
- 전체 논리 높이는 기본 추정 높이에 측정 구간의 차이를 더해 계산한다. 매번 전체 rowCount 길이의 Row/height/key 배열을 생성하지 않는다.
- Viewport 높이 인덱스는 block 단위 누적 합과 측정 차이를 관리한다. `src/virtual-layout.ts`의 dense CSR 인덱스와 역할을 구분하고 논리/물리 스크롤 변환은 공유한다.
- 보관 중인 block만 희소 인덱스에 넣고 나머지 구간의 높이는 공통 추정값으로 계산한다. block 내부는 제한된 크기의 높이 배열을 사용할 수 있지만, 전체 block 수만큼의 숨은 metadata 배열을 만들지 않는다. offset 검색과 갱신은 전체 rowCount 선형 순회 없이 수행한다.
- 데이터 cache와 높이 cache를 분리한다. Row 객체를 지워도 유효한 높이 또는 block 높이 요약은 별도 한도 안에서 보존할 수 있다.
- 높이 cache도 명시적인 예산을 갖는다. 기본 예산은 데이터 cache보다 큰 64 block으로 시작하고 현재 필수 구간을 보호한다. 무제한 방문 이력을 유지하지 않는다.
- 높이 정보까지 퇴출하면 그 구간은 다시 추정 상태가 된다. 현재 anchor를 보정하고 재방문 시 다시 측정한다. 정확한 전체 과거 높이와 일정한 metadata 메모리를 동시에 보장한다고 문서화하지 않는다.
- 미측정 전체 Row의 추정치를 측정 한 건마다 평균으로 바꾸지 않는다. 대규모 데이터에서 작은 평균 변화가 큰 전체 높이 변화를 만들 수 있다. 추정 기준 변경은 명시적 layout revision으로 처리한다.

### 7.2 동시 변경과 사용자 입력

- dataset revision, layout revision, Row ID/절대 위치, DOM 연결 identity를 대조한 측정만 수용한다.
- 요청 도착·cache 퇴출·측정값 갱신은 한 commit의 일관된 snapshot에서 적용한다. stale 응답이나 폐기된 render가 현재 높이 인덱스를 수정하면 안 된다.
- 미수신 anchor는 해당 dataset의 절대 인덱스로 추적하고 Row 수신 후 실제 ID와 연결한다. dataset revision이 바뀌면 과거 인덱스의 업무 동일성을 가정하지 않는다.
- 높이 보정으로 요청 구간이 조금 바뀌어도 동일 block을 반복 요청하거나 취소·재요청하지 않도록 요청 단위를 안정화한다.
- 빠른 wheel, 왕복 스크롤, thumb drag 도중에는 사용자 입력 의도와 anchor 보정의 우선순위를 제어한다. 움직임이 끝난 뒤 stale 보정으로 이전 위치로 돌아가지 않아야 한다.
- Column resize 중에는 렌더된 Row를 재측정하고 offscreen 측정값을 invalid 처리한다. 보정·요청·re-render가 매 pixel마다 전체 dataset 비용으로 증폭되지 않게 한다.

### 7.3 사용자에게 보장할 결과

- 측정 전 전체 스크롤 길이는 추정값이다. 측정·cache 정책에 따라 thumb 크기가 변할 수 있다.
- Row 겹침·누락, 잘못된 데이터 표시, 끝 구간 접근 불가, cache/request 무제한 증가는 허용하지 않는다.
- 안정화 후 동일 anchor와 내부 offset은 clamp가 필요한 경우를 제외하고 1 CSS px 이내로 유지하는 것을 geometry 기준으로 삼는다.
- 원격 데이터 변경·Row 삭제·너비 변경 후 존재하지 않는 과거 pixel 위치까지 동일하게 보장하지 않는다.
- 자동 높이 결합 성능이 검증되지 않으면 해당 항목을 미완료로 남긴다. 자동으로 고정 높이로 전환하여 통과시킨 것으로 처리하지 않는다.

### 10.2 브라우저·성능 판정

- 기존 100,000 Row 고정 높이와 10,000 Node Tree의 focused perf를 변경 전 먼저 실행한다.
- 자동 높이 CSR 100,000 Row와 Viewport 논리 1,000,000 Row의 전용 `@perf`를 추가한다. 명시적 기본 cache·block·overscan과 Row 최소 높이를 고정하여 재현한다.
- DOM/observer 수는 현재 렌더 window와 overscan의 함수여야 하며 전체 rowCount나 방문 거리와 비례해서 증가하면 안 된다.
- 데이터/요청/error/높이 metadata 각각의 effective 상한을 직접 assert한다. heap 하나만으로 bounded cache를 증명하지 않는다.
- 최소 20개 떨어진 구간 방문과 왕복·재방문 후에도 상한을 유지하고, unmount 시 listener·Observer·요청을 정리한다.
- 높이 캐시 퇴출 테스트는 설정한 예산을 실제 초과하는 block을 방문한다. 작은 테스트 예산으로 퇴출 횟수와 재방문 측정을 직접 확인하고, 기본 64 block 예산에서도 초과 방문을 검증한다.
- 실제 pointer/wheel/keyboard로 핵심 사용자 동작을 검증한다. 큰 위치 setup이나 반복 자원 계측의 programmatic scroll은 실제 thumb drag 검증과 분리하여 기록한다.
- geometry는 같은 layout snapshot에서 Row ID, bounds, anchor offset을 읽는다. 비동기 데이터·이미지 측정이 완료된 뒤 안정화 기준을 확인한다.
- 새로운 frame/long-task 지표는 전체 렌더·layout을 포함하여 수집한다. 단순 `scroll` dispatch 함수 실행 시간만으로 체감 스크롤 성능을 주장하지 않는다.
- 고정 높이 baseline의 기존 성능/메모리 기준을 유지한다. 신규 모드는 측정 workload와 환경을 고정하고 결과를 기록하며, 실패 후 assertion을 완화해 통과시키지 않는다.
- 신규 모드도 초기 계측 후 본 구현 검증 전에 frame/long-task 허용치를 명시한다. 요청 지연은 mock 서버의 고정 지연과 분리하고, 응답 후 안정화·사용자 입력 처리 지연을 검증한다.
- 제품 자동 검증은 현재 Chromium 범위다. 실제 native scrollbar 계측과 로컬 자원 검증을 hosted/일반 E2E와 구분한다. 미실행 브라우저의 지원 증거로 확대하지 않는다.

### 10.3 명령과 실행 시점

다음 명령은 **제품 구현 단계에서 실행할 계획**이다. 이 문서 작성 시 실행한 결과가 아니다.

```sh
# P0: 변경 전 관련 baseline
npm run test:perf -- test/playwright/specs/virtualization.spec.ts test/playwright/specs/tree-grid.spec.ts --workers=1

# P1~P5: 추가/수정한 focused 계약
npm run test:run -- test/tree-core.test.ts test/tree-row-drag-core.test.ts test/tree-table.test.tsx test/virtual-layout.test.ts test/row-height.test.tsx test/viewport-data.test.ts test/viewport-table.test.tsx
npm run test:e2e -- test/playwright/specs/tree-grid.spec.ts test/playwright/specs/tree-row-drag.spec.ts test/playwright/specs/viewport-datasource.spec.ts --workers=1
npm run test:perf -- test/playwright/specs/viewport-datasource.spec.ts test/playwright/specs/viewport-physical-scrollbar.spec.ts --workers=1

# P6: 공개 문서와 해당 예제
npm run test:run -- test/user-docs.test.ts

# P7: 마지막 의미 있는 변경 후 최종 gate
npm run verify
npm run test:e2e -- --workers=1
npm run test:perf -- --workers=1
npm run verify:package-artifact
git diff --check
```

- 위 파일명은 추가할 focused spec을 포함한다. 기존 `table-interaction.test.tsx`, Row Expand, Column Pinning, Grouping/Filter, Cross-Table, memory audit에도 영향 회귀를 추가한다.
- 새 쿼리/비동기 입력과 신뢰 경계를 포함하므로 구현 diff의 보안 민감 부분은 모듈 security routing으로 평가한다. 결정적 `verify` 게이트와 역할을 구분하고, 명시적 요청 없이 repository-wide/deep scan을 추가하지 않는다.
- 제품 코드 또는 테스트 계약을 의미 있게 고친 뒤 해당 전체 gate를 재실행한다. 동일 커밋의 환경 실패는 원인 확인 후 실패/영향 명령만 재실행하고 성공한 무관한 검증은 반복하지 않는다.
- `listen EPERM`은 우선 실행 환경 실패로 분류한다. 기존 기준선에서도 재현되는 성능 실패와 신규 회귀를 구분한다.
