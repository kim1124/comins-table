# Comins Table 0.1.7 Row Grouping 및 Column Filtering 구현 계획

- 작성일: 2026-08-25
- 상태: 구현 준비 완료
- 기준 브랜치: `main`
- 기준 커밋: `5ae35c10e5583531b65d363060f7f24408692714`
- 공통 정책: Comins Contract v1.7
- 대상 패키지: `comins-table` 0.1.6 → 0.1.7

## 1. 목표

0.1.7에서 다음 두 기능을 CSR controlled data 계약으로 제공한다.

1. flat `TData`를 하나 이상의 Column 기준으로 그룹화하는 Row Grouping
2. Column별 조건을 Header에서 편집하고 source Row를 필터링하는 Column Filtering

두 기능은 `data`를 변형하거나 synthetic group 값을 application state에 주입하지 않는다. Table이 파생한 visible projection만 변경하며 application-owned `data`, business Row ID, `dataIndex`, `onChangeData` 계약은 유지한다.

## 2. 조사 근거

계획 작성 시 다음 현재 저장소 표면을 직접 확인했다.

- `AGENTS.md`의 Contract v1.7 managed block과 canonical `COMINS_CONTRACT.md`
- `src/core.ts`, `src/index.tsx`, `src/virtual-layout.ts`, `src/row-detail.tsx`의 state, sorting, selection, Row Detail, virtualization 흐름
- `src/component-renderer.tsx`의 Header popover positioning, outside pointer, `Escape`, focus 복귀 패턴
- `src/table-icons.tsx`, `THIRD_PARTY_NOTICES.md`, license gate의 Radix icon inventory
- `docs/user/06-header.md`, `docs/ko/06-header.md`의 future Column Filter 위치·event 격리·controlled state 계약
- 기존 Row Grouping 설계의 group ID, membership, aggregation, leaf-only interaction, virtual slot 설계
- 현재 Playground registry, option guide, Korean/English docs parity, unit/type/Playwright/performance gate

`docs/superpowers/`의 이전 문서는 기술 조사 자료로만 사용한다. 비활성화된 Superpowers 실행 절차와 미구현 Column Pinning 선행 조건은 이 계획의 권한, 순서 또는 완료 조건이 아니다.

외부 제품 비교나 웹 조사는 사용하지 않았다. 공개 API와 구현 결정에 필요한 사실을 현재 저장소에서 확인할 수 있었기 때문이다.

## 4. 공통 불변조건

- `data`와 `onChangeData`는 기존 application-owned source array 계약을 유지한다.
- synthetic group Row는 `TData`, business Row ID 또는 source `dataIndex`를 갖지 않는다.
- leaf callback의 `row.data`, `row.id`, `row.dataIndex` 의미를 변경하지 않는다.
- leaf callback의 `row.index`만 최종 visible leaf 순서를 나타낸다.
- group/filter 파생 결과를 `state.rows`에 되쓰지 않는다.
- 기존 package export `.`, `./core`, `./clipboard`, `./selection`, `./styles.css`를 유지하고 새 package subpath를 추가하지 않는다.
- 새 runtime dependency를 추가하지 않는다.
- React/React DOM peer dependency와 client-only boundary를 유지한다.
- group/filter가 비활성인 경우 기존 projection과 fixed-size virtualization fast path의 결과가 같아야 한다.
- unknown Column, invalid operator, invalid runtime value는 throw하지 않고 해당 rule을 무효화한다. application callback 예외는 기존 render error 동작대로 전파한다.

## 5. 공개 API 계획

### 5.1 Row Grouping

새 `src/grouping.ts`가 다음 공개 type과 private pure helper를 소유하고 root entry에서 공개 type만 re-export한다.

```ts
export type CominsRowGroupKey =
  | string
  | number
  | boolean
  | null
  | Date;

export type CominsRowGroupingSourceRow<TData> = {
  data: TData;
  dataIndex: number;
  id: CominsRowId;
};

export type CominsRowGroupingCriterion<TData> = {
  columnId: string;
  getKey?: (params: CominsRowGroupingValueParams<TData>) =>
    | CominsRowGroupKey
    | undefined;
  getLabel?: (params: CominsRowGroupingLabelParams<TData>) => React.ReactNode;
};

export type CominsRowGroupingCriterionInput<TData> =
  | string
  | CominsRowGroupingCriterion<TData>;

export type CominsRowGroupAggregation =
  | "avg"
  | "count"
  | "max"
  | "min"
  | "sum";

export type CominsRowGroupingConfig<TData> = {
  aggregations?: Readonly<Partial<Record<string, CominsRowGroupAggregation>>>;
  criteria: readonly CominsRowGroupingCriterionInput<TData>[];
  expandedGroupIds?: readonly string[];
  onChangeExpandedGroupIds?: (groupIds: string[]) => void;
};
```

`rowGrouping`은 flat table 전용이다. `expandedGroupIds`가 source of truth이며 callback이 없으면 disclosure는 disabled read-only 상태다. Tree, pagination, loading modes 및 draggable Row와의 금지 조합은 type과 runtime 양쪽에서 차단한다.

### 5.2 Column Filtering

새 `src/filtering.ts`가 public filter type과 private normalization/evaluation helper를 소유한다.

```ts
export type CominsColumnFilterKind =
  | "boolean"
  | "date"
  | "number"
  | "text";

export type CominsColumnFilterOperator =
  | "contains"
  | "endsWith"
  | "equals"
  | "greaterThan"
  | "greaterThanOrEqual"
  | "isEmpty"
  | "isNotEmpty"
  | "lessThan"
  | "lessThanOrEqual"
  | "notContains"
  | "notEquals"
  | "startsWith"
  | "between";

export type CominsColumnFilterConfig<TData, TValue = unknown> = {
  caseSensitive?: boolean;
  getValue?: (params: CominsCellFormatParams<TData, TValue>) => unknown;
  kind: CominsColumnFilterKind;
};

export type CominsColumnFilterRule = {
  columnId: string;
  operator: CominsColumnFilterOperator;
  value?: string | number | boolean | null;
  valueTo?: string | number | null;
};

export type CominsColumnFilterModel = readonly CominsColumnFilterRule[];

export type CominsColumnFilteringConfig = {
  model: CominsColumnFilterModel;
  onChangeModel?: (model: CominsColumnFilterRule[]) => void;
  onChangeOpenColumnId?: (columnId: string | null) => void;
  openColumnId?: string | null;
};
```

`CominsTableColumn<TData, TValue>`에 다음을 추가한다.

```ts
filter?: CominsColumnFilterConfig<TData, TValue>;
```

flat table prop에는 다음을 추가한다.

```ts
columnFiltering?: CominsColumnFilteringConfig;
```

`model`과 `openColumnId`는 application-owned controlled state다. callback이 없으면 대응 control은 disabled read-only 상태를 유지한다. Table은 별도의 filter model source of truth를 만들지 않는다.

### 5.3 Prop 조합

public prop type은 다음 세 flat branch를 구분한다.

1. ordinary flat: grouping/filtering 없음, 기존 loading·pagination·Row drag 조합 유지
2. filtered flat: `columnFiltering` 존재, pagination·virtualization 지원, lazy/infinite loading과 Row drag 금지
3. grouped flat: `rowGrouping` 존재, `columnFiltering` 선택 가능, pagination·lazy/infinite loading과 Row drag 금지

`CominsTreeTableProps`는 `rowGrouping?: never`, `columnFiltering?: never`를 노출한다. TypeScript를 우회한 JavaScript caller에 대해서도 prohibited path가 실행되지 않도록 runtime guard를 둔다.

## 6. Filter 의미

### 6.1 Rule normalization

- unknown 또는 filter 미설정 Column rule 제거
- 같은 Column의 중복 rule은 첫 번째 valid rule만 유지
- Column kind에서 지원하지 않는 operator 제거
- `isEmpty`, `isNotEmpty`는 filter value 없이 유효
- text value는 string으로 정규화하고 기본 case-insensitive 비교
- number는 finite number만 유효
- date model value는 `YYYY-MM-DD`이고 Row 값은 같은 UTC calendar day로 정규화
- boolean은 `true` 또는 `false`만 유효
- `between`은 두 endpoint가 모두 유효할 때만 활성화하며 낮은 값과 높은 값을 정규화

### 6.2 Empty와 비교

- empty는 `null`, `undefined`, 빈 string이다.
- 공백 string은 text filter에서 값으로 취급한다.
- invalid Date, `NaN`, infinity는 비교 operator와 일치하지 않는다.
- text `contains`, `startsWith`, `endsWith`는 normalized string에 적용한다.
- Column별 rule은 하나이고 서로 다른 Column rule은 AND로 결합한다.

### 6.3 Projection 순서

```text
source data/rowIds
  → valid filter rules
  → filtered source indexes
  → optional group membership/aggregation
  → hierarchy-first group/leaf sorting
  → pagination when ungrouped
  → fixed/mixed virtualization
  → rendered group/data/detail rows
```

filter 변경은 source `dataIndex`나 business Row ID를 바꾸지 않는다. visible leaf index만 새 projection에 맞게 다시 계산한다.

## 7. Row Grouping 내부 설계

### 7.1 Stable identity

- group ID는 `comins-group:` prefix와 length-prefixed typed path segment로 만든다.
- string, finite number, boolean, valid Date, empty, unsupported value를 서로 다른 key type으로 정규화한다.
- label, sort, expanded state는 group ID에 영향을 주지 않는다.
- criteria 순서, key callback, key 값 변경은 새 group ID를 만들 수 있다.

### 7.2 세 단계 derivation

1. membership/aggregation: filtered source index, Row ID, normalized criteria와 aggregation config
2. ordering: sort model로 sibling group과 lowest-level leaf 정렬
3. projection: ordered metadata와 controlled expanded group ID로 visible slot 생성

expansion 변경은 membership과 aggregation을 다시 만들지 않는다.

### 7.3 Memory shape

- lowest-level group만 direct leaf source-index array 보유
- parent group은 child group ID와 reducer state만 보유
- group metadata에 `TData` 복사 금지
- membership은 `filtered row count × grouping depth`의 선형 pass
- visible projection은 expanded branch만 순회

### 7.4 Aggregation

- `count`는 empty value를 포함한 descendant leaf 수
- `sum`, `avg`, `min`, `max`는 finite number만 사용
- numeric value가 없으면 empty output
- filter가 활성화되면 통과한 descendant leaf만 group aggregate에 포함
- group label cell이 aggregate Column과 같으면 label이 우선

## 8. Rendering 및 interaction

### 8.1 Group Row

- group Row는 native `<tr>` 사용
- 첫 visible Column cell은 `<th scope="row">`, 나머지는 `<td>`
- label cell에 disclosure, depth indentation, grouping Column label, group label 표시
- Column Pinning이 없으므로 현재 visible Column order와 width만 공유
- source grouping Column은 별도 column layout이 숨기지 않는 한 계속 표시
- group Row height는 정확히 `rowHeight`
- group Row는 normal Cell renderer, formatter, tooltip, component를 호출하지 않음

### 8.2 Filter Header

- Filter button은 Header sort metadata 뒤, right component slot 앞, resize hit area 전에 배치
- 현재 Radix dependency의 `MixerHorizontalIcon`을 private semantic icon `filter`로 사용
- icon import inventory, notice, license gate를 함께 갱신
- button은 `aria-expanded`, `aria-controls`, Column별 accessible name, active state 제공
- pointer/click/double-click/keyboard event를 Header sort, resize, move에서 격리
- popover는 기존 Header menu의 fixed positioning, viewport clamp, outside pointer, `Escape`, focus 복귀 패턴 재사용
- popover는 filter kind에 맞는 operator와 value control, Clear action 제공
- model 변경은 매번 전체 next model을 `onChangeModel`로 전달
- open 변경은 `onChangeOpenColumnId`로 전달
- Column Move placeholder에서는 Filter control과 popover를 비활성화하고 숨김

### 8.3 Selection, Clipboard, Row Detail

- group Row는 Row/Cell/range selection, clipboard, Row callbacks, drag, imperative movement에서 제외
- filter 또는 group collapse로 숨겨진 selected business Row ID는 dormant 상태로 보존
- 숨겨진 active Cell/range endpoint는 정확히 한 번 제거하고 row ID selection은 유지
- copy/paste와 Shift selection은 현재 visible leaf만 순회
- grouped/filtered leaf Row Detail은 기존 leaf payload와 controlled expanded Row ID를 유지
- 숨겨진 Detail owner ID는 dormant 상태로 보존하고 다시 visible해지면 복원

### 8.4 Focus 및 scroll anchor

- user group collapse 후 disclosure focus 유지
- external collapse가 focused leaf를 숨길 때 nearest visible ancestor disclosure로만 focus 이동
- filter가 focused leaf를 숨기면 다음 visible leaf Cell, 이전 visible leaf Cell, Filter button 순서로 focus 복구
- focus가 Table 밖에 있으면 projection 변경이 focus를 가져오지 않음
- group expansion/collapse와 filter 변경 전에 first fully visible stable slot key와 viewport offset을 캡처
- anchor가 제거되면 nearest surviving leaf 또는 관련 group/filter Header를 fallback으로 사용
- correction은 한 animation frame에 coalesce하고 legal scroll range로 clamp

## 9. Virtualization 및 Summary

- group과 data를 구분하는 공통 private projection slot을 사용한다.
- 모든 slot이 `rowHeight`이면 arithmetic fixed-size lookup을 유지한다.
- expanded Row Detail이 실제로 다른 높이를 만들 때만 `CominsHeightIndex`를 사용한다.
- group slot은 visible leaf index를 증가시키지 않는다.
- Detail `<tr>`은 owner data slot에 포함되고 별도 visible index를 갖지 않는다.
- ungrouped filtered table은 filtered source-index array로 기존 fixed virtualization을 수행한다.
- Summary built-in/custom aggregation input은 filter를 통과한 original leaf `TData`만 사용한다.
- group Row와 group aggregate display value는 Summary input에 포함하지 않는다.
- export helper는 기존대로 caller가 전달한 Row만 serialize하며 filter model을 암묵적으로 적용하지 않는다.

## 13. 완료 조건

0.1.7 feature implementation은 다음 조건을 모두 만족해야 완료로 처리한다.

- Row Grouping과 Column Filtering public type이 문서와 일치한다.
- prohibited prop 조합이 type test에서 실패하고 untyped runtime에서도 inert하다.
- synthetic group Row가 `TData` 또는 leaf callback으로 노출되지 않는다.
- group ID, multi-level membership, built-in aggregation과 hierarchy sort가 deterministic하다.
- filter model과 open Column이 application-owned controlled state다.
- text/number/date/boolean operator가 정의된 normalization 규칙대로 동작한다.
- filter → grouping → sorting → pagination/virtualization 순서가 unit/browser evidence로 확인된다.
- hidden leaf Row ID와 Detail/group expansion state가 dormant 상태로 보존된다.
- hidden Cell/range state와 focus/scroll anchor가 정의된 규칙대로 복구된다.
- group/filter 비활성 기존 table behavior와 public entrypoint가 회귀하지 않는다.
- Column Pinning과 Visual Fill Handle이 구현·문서·옵션 목록에 지원 기능으로 섞이지 않는다.
- Korean/English docs, Playground, README와 option guide가 같은 범위를 설명한다.
- focused unit/type/browser/performance gate와 최종 broad gate가 모두 통과한다.
- release publish와 provider mutation은 별도 승인 전 수행되지 않는다.

## 14. 잔여 리스크

- 100,000 Row에서 각 keystroke마다 filtering/grouping을 재계산하면 callback identity와 model object churn이 성능에 영향을 줄 수 있다. Pure layer별 memoization과 performance fixture로 제한한다.
- Header는 overflow-hidden split table 구조이므로 popover 위치, horizontal scroll, Column Move 중 open state 회귀 가능성이 있다. 기존 fixed menu positioning 패턴과 browser geometry assertion이 필요하다.
- filtering으로 대량 slot이 제거되거나 grouping collapse와 동시에 projection이 바뀔 때 focus/scroll fallback이 불안정할 수 있다. stable slot key 기반의 결합 test를 필수로 둔다.
- Date filter는 timezone 혼동 가능성이 있으므로 0.1.7은 `YYYY-MM-DD` UTC calendar-day 계약만 지원한다.
- Tree, lazy/infinite loading, Row drag와의 결합은 type/runtime에서 차단하지 않으면 부분 동작으로 오해될 수 있으므로 negative coverage가 필수다.
- main post-merge Verify가 계획 작성 시점에 queued 상태였으므로 구현 branch 시작 전 최신 main CI 상태를 다시 확인한다.
