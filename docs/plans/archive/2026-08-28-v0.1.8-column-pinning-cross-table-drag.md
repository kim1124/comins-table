- 작성일: 2026-08-28
- 상태: 로컬 구현 및 검증 완료
- 기준 브랜치: `main`
- 기준 커밋: `2439e10c4fe9d55a0018fa69c5adaeea6697b902`

- 대상 패키지: `comins-table` 0.1.7 → 0.1.8

## 1. 목표

0.1.8에서 다음 두 기능을 application-owned controlled model로 제공한다.

1. 왼쪽 또는 오른쪽에 고정되고 Column Move로 위치를 변경할 수 없는 Column Pinning
2. 서로 다른 `CominsTable` 인스턴스 사이에서 실제 Row 및 Group 모델을 이동하는 Cross-Table Drag

Cross-Table Drag는 기존 같은 Table 내부 Row/Group Drag를 대체하지 않는다. 같은 Table의 이동은 기존 `onChangeData`와 `onChangeGroups` 계약을 유지하고, 서로 다른 Table 사이의 이동만 명시적으로 공유한 Coordinator가 하나의 원자적 Transfer 결과를 전달한다.

Group Transfer는 Group 정의만 옮기지 않는다. Group과 해당 Group을 참조하는 모든 Row를 하나의 bundle로 옮기며 빈 Group도 유효한 이동 대상과 이동 source로 유지한다.

## 3. 확정된 제품 결정

### 3.1 Cross-Table Drag

- application이 생성한 Coordinator 객체를 Drag에 참여하는 Table에 명시적으로 전달한다.
- 전역 문자열 Registry 또는 React Provider를 필수 구조로 사용하지 않는다.
- 같은 Coordinator와 같은 `scope`를 공유하는 Table만 서로 이동할 수 있다.
- `tableId`는 Coordinator와 scope 안에서 고유해야 한다.
- 출발·도착 Table은 같은 `TData`와 `TGroup` 구조를 사용한다.
- V1은 move만 지원하고 copy/clone은 지원하지 않는다.
- 한 번의 Drag에서 Row 하나 또는 Group 하나만 이동한다.
- flat Table의 Row는 다른 flat Table로 이동할 수 있다.
- grouped Table의 Row는 다른 grouped Table의 특정 Group으로 이동할 수 있다.
- Group은 Group과 전체 소속 Row를 함께 다른 grouped Table로 이동한다.
- 일반 Table과 grouped Table 사이의 구조 변환은 지원하지 않는다.
- Tree Drag는 별도 기능으로 구현한다.
- empty flat Table, empty Group, collapsed Group과 Group이 하나도 없는 grouped Table을 유효한 target으로 지원한다.
- source Group의 마지막 Row가 이동해도 source Group은 유지한다.
- Group 자체를 이동하면 source의 Group 모델에서는 해당 Group을 제거한다.

### 3.2 충돌 정책

- 동일 Row ID 또는 Group ID 충돌의 기본 정책은 `"reject"`다.
- target Table이 제공하는 동기식 conflict resolver callback으로 `"overwrite"` 또는 `"reject"`를 선택할 수 있다.
- callback이 없거나 `undefined` 또는 잘못된 값을 반환하면 `"reject"`로 처리한다.
- `"overwrite"`는 merge가 아니라 동일 ID target entity의 교체다.
- Row overwrite는 target의 동일 ID Row를 제거한 뒤 source Row를 요청된 Drop 위치에 삽입한다.
- Group overwrite는 target의 동일 ID Group과 그 Group에 소속된 모든 Row를 제거한 뒤 source Group bundle로 교체한다.
- Group overwrite의 requested target이 충돌 Group 자체면 기존 충돌 Group index를 사용한다. 다른 Group을 target으로 지정했으면 충돌 Group을 제거한 후 보정한 requested before/after 위치를 사용한다.
- Group overwrite에서 제거된 target Group의 첫 member 위치가 있으면 source member Rows를 해당 data index에 삽입하고, 없으면 target data 끝에 삽입한다.
- source member Rows의 상대 순서는 유지한다.
- V1에 merge, ID 재생성 또는 asynchronous conflict dialog protocol은 포함하지 않는다.

### 3.3 UI 상태

- Transfer 대상은 domain model인 `data`와 선택적인 `groups`다.
- Group expanded IDs, Row Detail expanded IDs와 selection은 다른 Table로 자동 이전하지 않는다.
- source에서 더 이상 유효하지 않은 Row/Group 기반 UI 상태는 기존 normalization 계약으로 정리하거나 무시한다.
- overwrite로 동일 ID가 target에 남는 경우 target이 이미 소유하던 ID 기반 UI 상태는 target 정책대로 유지될 수 있다.
- 성공한 controlled update 후 keyboard accessibility를 위해 destination Row 또는 Group Drag handle로 focus를 복구한다.
- focus 복구가 불가능하거나 application이 Transfer 결과를 반영하지 않으면 가장 가까운 target Table root로 fallback하고 내부 optimistic model은 만들지 않는다.

### 3.4 Column Pinning

- leaf Column 또는 전체 Header Group을 `"left"` 또는 `"right"`로 pin할 수 있다.
- configured pinned Column/Group은 Column Move로 위치를 변경할 수 없다.
- 기존 `lockPosition`은 독립적으로 유지하며, `pinned`는 추가적인 position-lock 조건이다.
- grouped Header child는 독립적으로 pin하지 않고 Group이 전체 child block의 pin side를 소유한다.
- application이 설정한 configured pin intent와 컨테이너 크기에 따라 계산되는 effective pin state를 분리한다.
- 좁은 컨테이너의 temporary demotion은 configured state와 serialized layout을 변경하지 않는다.
- 컨테이너가 다시 넓어지면 configured pin을 자동 복원한다.
- Header, Body, Skeleton과 Summary의 Column Cell은 같은 effective order, width와 sticky offset을 사용한다.
- full-width Group Row와 Row Detail은 하나의 non-sticky spanning Cell을 유지한다.
- Tree Grid Column Pinning은 V1 범위에서 제외한다.

## 5. 공통 불변조건

- `data`, `groups`와 최종 React state의 source of truth는 application이다.
- Table은 Cross-Table Drop 후 내부 optimistic Row/Group 배열을 만들지 않는다.
- Cross-Table Drop은 source/target `onChangeData` 또는 `onChangeGroups`를 각각 호출하지 않는다.
- 같은 Table 내부 Drop은 기존 callback과 helper 계약을 그대로 사용한다.
- business Row ID와 Group ID는 Transfer 전후에 유지한다.
- grouped Row transfer에 target `setRowGroupId`가 필요하며, 반환된 Row의 `getRowId`가 바뀌면 fail closed 한다.
- conflict resolver와 `canTransfer`는 model mutation 전에 호출한다.
- rejected/no-op Drop은 application callback을 발생시키지 않는다.
- pointermove에서는 전체 Row/Group 배열 복사, 정렬 또는 DOM 전체 검색을 수행하지 않는다.
- edge auto-scroll frame도 현재 target viewport와 pointer 좌표만 사용하고 model transition은 수행하지 않는다.
- 실제 transition은 pointerup의 latest registered snapshot에서 한 번 계산한다.
- package exports `.`, `./core`, `./clipboard`, `./selection`, `./styles.css`를 유지한다.
- DOM module-evaluation access를 추가하지 않고 client-only boundary를 유지한다.
- 새 dependency를 추가하지 않는다.

## 6. Cross-Table Drag 공개 API 목표

새 `src/table-transfer.ts`가 public type, Coordinator와 pure transition을 소유하고 root entry에서 export한다. 새 package subpath는 추가하지 않는다.

### 6.1 Coordinator

```ts
export type CominsTableTransferConflictPolicy = "overwrite" | "reject";

export type CominsTableTransferCoordinatorOptions<TData, TGroup> = {
  onTransfer: (
    result: CominsTableTransferResult<TData, TGroup>,
  ) => void;
};

export function createCominsTableTransferCoordinator<
  TData,
  TGroup = never,
>(
  options: CominsTableTransferCoordinatorOptions<TData, TGroup>,
): CominsTableTransferCoordinator<TData, TGroup>;
```

Coordinator는 Table의 DOM root와 latest controlled model snapshot만 등록한다. application data를 보관하거나 변경하지 않는다. 같은 객체 참조를 사용하므로 Portal과 서로 다른 React root에서도 동작하며 module-global Registry를 만들지 않는다.

### 6.2 Table 설정

```ts
export type CominsTableTransferConfig<TData, TGroup = never> = {
  canTransfer?: (
    intent: CominsTableTransferIntent<TData, TGroup>,
  ) => boolean;
  coordinator: CominsTableTransferCoordinator<TData, TGroup>;
  resolveConflict?: (
    conflict: CominsTableTransferConflict<TData, TGroup>,
  ) => CominsTableTransferConflictPolicy | undefined;
  scope: string;
  tableId: string;
};
```

flat/grouped Table prop에 `tableTransfer`를 opt-in으로 추가한다. Tree, filtered, infinite/lazy branch에는 `tableTransfer?: never`를 적용하고 JavaScript caller를 위한 runtime guard도 둔다.

- `canTransfer`와 `resolveConflict`는 target Table의 latest 설정을 사용한다.
- `canTransfer`가 `false`면 conflict resolver를 호출하지 않고 reject한다.
- duplicate `tableId` 등록은 해당 scope의 cross-table Drop을 fail closed 한다.
- source와 target의 Coordinator 또는 scope가 다르면 invalid target이다.

### 6.3 Conflict payload

```ts
export type CominsTableTransferConflict<TData, TGroup> =
  | {
      kind: "row";
      rowId: CominsRowId;
      source: CominsTableTransferRowEndpoint<TData>;
      target: CominsTableTransferRowEndpoint<TData>;
    }
  | {
      groupId: CominsRowId;
      kind: "group";
      source: CominsTableTransferGroupEndpoint<TData, TGroup>;
      target: CominsTableTransferGroupEndpoint<TData, TGroup>;
    };
```

payload는 resolver가 reject/overwrite를 판단하는 데 필요한 충돌 entity만 노출한다. resolver가 반환한 policy는 최종 result details에도 포함하여 application이 destructive overwrite를 감사하거나 기록할 수 있게 한다.

### 6.4 Atomic result

```ts
export type CominsTableTransferResult<TData, TGroup> = {
  details: CominsTableTransferDetails<TData, TGroup>;
  kind: "group" | "row";
  source: {
    data: TData[];
    groups?: TGroup[];
    tableId: string;
  };
  target: {
    data: TData[];
    groups?: TGroup[];
    tableId: string;
  };
};
```

application은 한 번의 `onTransfer`에서 두 Table의 controlled state를 함께 갱신한다. React batching에 의존하여 두 개의 library callback을 조합하지 않는다.

### 6.5 Pure helper

UI와 application JavaScript가 같은 결과를 만들 수 있도록 다음 root-exported pure helper를 제공한다.

```ts
export function transferCominsRowBetweenTables<TData, TGroup = never>(
  input: CominsRowBetweenTablesInput<TData, TGroup>,
): CominsTableTransferResult<TData, TGroup> | null;

export function transferCominsGroupBetweenTables<TData, TGroup>(
  input: CominsGroupBetweenTablesInput<TData, TGroup>,
): CominsTableTransferResult<TData, TGroup> | null;
```

helper는 immutable next arrays를 반환하며 invalid/no-op은 `null`을 반환한다. Coordinator UI path도 이 helper를 사용한다.

## 7. Drop 및 모델 전이 규칙

### 7.1 Row

- ordinary Row target은 target Row의 source data index 앞에 삽입한다.
- flat empty-state 또는 Table body target은 target data 끝에 append한다.
- grouped Row target은 해당 target Row 앞에 삽입하고 target Group membership을 적용한다.
- grouped Group Row target은 해당 Group의 마지막 member 뒤에 삽입한다.
- empty Group에는 target data 끝에 삽입하고 target Group membership을 적용한다.
- source Row를 source data에서 제거한 뒤 target insert index를 정규화한다.
- target `setRowGroupId`는 target Table의 latest callback을 사용한다.
- `setRowGroupId`가 없거나 반환 Row의 business ID가 달라지면 invalid다.
- duplicate Row ID는 target resolver가 overwrite를 명시한 경우에만 target duplicate를 제거한다.

### 7.2 Group

- Group target의 수직 중앙을 기준으로 before/after 위치를 계산한다.
- Group이 없는 grouped Table의 body target은 첫 Group으로 append한다.
- source Group의 member Rows는 source data에서 한 번의 stable partition으로 추출한다.
- source `groups`에서는 source Group을 제거한다.
- target `groups`에는 requested before/after 또는 empty append 위치로 source Group을 삽입한다.
- non-conflict transfer의 member Rows는 target data 끝에 source 상대 순서대로 append한다.
- overwrite는 확정된 충돌 규칙에 따라 target Group과 member Rows를 먼저 제거하고 보정된 위치에 source bundle을 삽입한다.
- empty Group은 Row transition 없이 Group arrays만 변경한다.

### 7.3 취소와 stale state

- pointerup에서 source Row/Group ID와 target ID를 latest snapshots에서 다시 찾는다.
- source 또는 target이 unmount됐거나 identity가 사라졌으면 reject한다.
- Drag 중 data/groups가 바뀌어 requested target이 없어지면 reject한다.
- `pointercancel`, `Escape`, window blur와 component unmount는 marker, ghost, pending focus와 global listener를 정리한다.
- callback이 controlled props를 반영하지 않으면 다음 render도 이전 모델을 표시한다.

### 7.4 Target edge auto-scroll

- source와 다른 유효한 target Table body viewport 안에 pointer가 있을 때만 동작한다.
- target viewport의 상단 또는 하단 `min(40px, viewportHeight / 2)` 영역을 activation band로 사용한다.
- edge에 가까울수록 빨라지는 선형 속도를 사용하고 최대 속도는 `720 CSS px/s`로 제한한다.
- `requestAnimationFrame` timestamp delta를 사용하여 display refresh rate와 무관한 속도를 계산하고, background 복귀 시 큰 jump를 막기 위해 frame delta를 최대 32ms로 제한한다.
- 한 시점에는 pointer가 위치한 target Table 하나만 scroll한다.
- target의 native physical `scrollTop`만 변경하고 기존 body scroll handler가 virtual projection과 compressed logical scroll을 갱신하게 한다.
- 각 accepted scroll frame 뒤에 같은 pointer 좌표로 Row/Group target을 다시 resolve하여 marker와 최종 Drop 위치를 갱신한다.
- content가 overflow하지 않거나 top/bottom boundary에 도달하면 frame loop를 중단한다.
- pointer가 activation band 또는 target Table을 벗어나거나 target이 invalid가 되면 즉시 중단한다.
- pointerup, `pointercancel`, `Escape`, blur, source/target unmount에서 pending frame을 취소한다.
- horizontal, page, source Table, 복수 Table 동시 auto-scroll은 V1에서 지원하지 않는다.
- 기존 same-Table Row/Group Drag의 scroll 동작은 변경하지 않는다.

## 8. Column Pinning 갱신 설계

### 8.1 공개 상태

```ts
export type CominsColumnPinned = "left" | "right";
```

다음 optional field를 기존 shape에 추가한다.

- `CominsTableColumn.pinned`
- `CominsTableColumnGroup.pinned`
- `CominsColumnRuntimeState.pinned`
- `CominsColumnGroupRuntimeState.pinned`

기존 `CominsColumnLayout` shape는 유지한다. 오래된 layout에 `pinned`가 없으면 center로 복원하고 unknown/invalid 값은 throw하지 않고 제거한다.

`getColumnLayout()`은 configured pin intent를 반환하고 `setColumnLayout()`은 normalized intent를 적용한다. 별도 imperative pin/unpin Ref method는 추가하지 않는다.

### 8.2 Atomic block과 effective zones

- canonical logical order는 기존 `columnOrder`다.
- ungrouped leaf는 하나의 block이다.
- valid Header Group은 visible children 전체를 가진 하나의 atomic block이다.
- group runtime/definition pin이 child pin보다 우선한다.
- derived order는 `[left][center][right]`이며 zone 안에서 canonical 상대 순서를 유지한다.
- DOM, visual, keyboard, selection과 Clipboard Column order를 같은 effective order로 맞춘다.

### 8.3 Responsive demotion

- 컨테이너 content width와 resolved numeric Column width snapshot만 사용한다.
- 컨테이너가 48px 이상이면 center에 최소 48px를 확보한다.
- pinned width가 이를 침범하면 넓은 side부터 inner block을 하나씩 center로 demote한다.
- left/right가 같으면 right side를 먼저 demote한다.
- Header Group은 원자적으로 demote한다.
- 컨테이너가 48px 미만이면 모든 configured pin을 effective center로 처리한다.
- `ResizeObserver`, accepted Column width, hide/show와 layout restore에서 재계산한다. Effective pinned block의 직접 resize는 self-demotion 전에 48px center budget 상한으로 제한한다.
- demotion은 `getColumnLayout()` 또는 `onChangeColumnLayout`을 변경하지 않는다.

### 8.4 렌더링

- 기존 Header, Body와 Summary table을 유지하고 별도 zone table을 만들지 않는다.
- left offset은 앞선 effective-left Column width의 누적값이다.
- right offset은 뒤따르는 effective-right Column width의 누적값이다.
- sticky cell은 opaque semantic background와 center-facing boundary marker를 갖는다.
- striped, selected, focused, Summary와 Skeleton 배경을 보존한다.
- 전체 empty/loading Cell은 non-sticky다.
- Summary `colSpan`이 effective zone 경계를 넘으면 내부 fragment로 나누고 첫 fragment만 content와 public test ID를 갖는다.
- Group Row는 현재 하나의 `<th scope="rowgroup" colSpan>`을 그대로 사용하고 pin fragment를 만들지 않는다.
- Row Detail도 현재 하나의 full-width non-sticky Cell을 유지한다.

### 8.5 Move, resize와 Drag 결합

- configured pinned Column/Group과 기존 `lockPosition` Column/Group은 Column Move source가 될 수 없다.
- center Column은 center zone 안에서만 reorder한다.
- temporarily demoted pinned block도 configured state를 기준으로 계속 position-locked다.
- pinned Column/Group resize는 허용한다. Effective pinned block은 다른 effective pin과 center 48px를 유지하는 최대 너비에서 제한하고, accepted width로 effective zone과 offset을 다시 계산한다.
- first visible Column이 pinned여도 Row Drag handle과 Row Detail disclosure pointer lifecycle을 유지한다.
- full-width Group Row의 Group Drag handle은 non-sticky Group content 안에 유지한다.

## 15. 잔여 리스크와 구현 중 확인 사항

- Cross-Table Coordinator generic이 JSX의 grouped `TGroup` 추론을 방해할 수 있으므로 type fixture를 pure helper 직후에 둔다.
- overwrite는 target entity와 member Rows를 제거하는 destructive model transition이다. resolver payload와 docs에서 삭제 범위를 명확하게 보여주고 default를 reject로 유지한다.
- application이 `onTransfer`에서 source와 target 중 하나만 반영하면 화면과 모델이 부분 반영될 수 있다. library는 이를 대신 복구할 수 없으므로 atomic state example과 문서로 책임을 명시한다.
- target `setRowGroupId`가 Row ID를 바꾸거나 Group 참조 무결성을 깨면 selection, Detail과 conflict 검사가 불안정해진다. fail-closed ID 검증과 문서가 필요하다.
- full-width Group Row는 pin zone별 Cell로 나뉘지 않으므로 horizontal scroll 시 Group content도 하나의 spanning surface로 이동한다. 이는 기존 `colSpan` 계약을 보존하는 의도된 동작이다.
- CSS sticky inside native table은 브라우저별 stacking과 background 차이가 있으므로 Chromium Playwright 결과만으로 Firefox/Safari 지원을 주장하지 않는다.
- target edge auto-scroll은 physical `scrollTop`을 움직이므로 compressed virtual scroll에서 logical target 갱신과 pointerup 직전 마지막 frame race를 browser test로 고정해야 한다.
- auto-scroll frame이 target re-render 또는 unmount와 겹칠 수 있으므로 Coordinator registration revision과 animation frame cleanup을 같은 lifecycle boundary에서 관리해야 한다.
- 실제 100,000 Row 성능과 lifecycle recovery는 알고리즘 분석만으로 완료 처리하지 않고 focused/full performance evidence로 확인한다.
